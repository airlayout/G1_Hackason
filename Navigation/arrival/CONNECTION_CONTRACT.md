# 巡回と作業の接続条件

この文書は将来の接続の意味と責任を定める。現行の押下実装へのadapterやROS actionは追加しない。
到着計測と押下機構の改良を独立して進めるため、関節数、腕、腰の軸、カメラの種類、押下経路を契約に含めない。

## 責任と渡す情報

| 担当 | 責任 |
|---|---|
| 巡回側 | 対象付近への移動、実測による停止確認、作業依頼、立ち位置変更の実行可否判断 |
| 作業側 | 観測からの実行可否判断、必要な位置変更の条件提示、押下・反応確認・復帰 |
| 共通の管理側 | 移動と作業の排他、実行権限の維持・失効、中止・異常の伝達、再開可否の確認 |

開始依頼には依頼を一意に識別するID、対象IDと目的（例: upボタン）、時刻・座標系付きの観測への参照、
身体状態と計測品質を含める。観測には出所・露光／受信時刻の区別・校正ID・不確かさを付ける。
特定のカメラや認識器、関節目標を必須にしない。作業側は不足する観測を理由付きで返せる。

作業開始前の応答は、実行可能・位置変更が必要・観測不足・実行不能を区別する。
実行可能という応答は移動許可や接触許可そのものではなく、同じ依頼IDの有効な排他状態でのみ実行を開始する。

## 位置変更と終了結果

位置変更の要求は対象に対する望ましい相対姿勢／領域、座標系、有効時刻、理由を示す。
作業側がベース速度や足の指令を直接送らない。巡回側が通行可能性と現在の制約を評価する。
変更前に作業側が移動可能な姿勢へ戻ったことを確認し、移動後は新しい観測で実行可否を判定し直す。
到着計測の分布を、そのまま押せる範囲や再接近先として固定登録しない。

終了結果は少なくとも次の3つを別々に持つ。

| 項目 | 意味 |
|---|---|
| 終了理由 | 正常終了、中止、実行不能、異常など |
| 押下の確認 | 対象の反応を確認、未確認、観測不足で不明。指令送信・指先接触だけを確認成功にしない |
| 移動再開可能 | 復帰状態を確認して可能、不可、状態不明。押下成否から推測しない |

通常の自動再開は、同一依頼IDについて押下確認済み・移動可能・排他の引き渡し完了・走行許可有効がそろった場合のみ。
押下結果不明で収納だけできた場合は保留する。無反応の場合も、自動で同じ押下を繰り返さない。
中止・異常で失効した許可を、作業完了を理由に再発行しない。

## 文書上のシナリオ確認

以下は契約の整合性の確認で、接続コードや実機の動作を検証した結果ではない。

| シナリオ | 期待する流れ | 確認点 |
|---|---|---|
| 正常完了 | 到着→停止確認→移動を排他→作業→反応確認→復帰確認→排他解除→巡回再開 | 到達通知だけで開始せず、押下確認だけで再開しない |
| 位置変更が必要 | 作業側が条件を返す→移動可能姿勢を確認→巡回側が再接近→再観測 | 作業側は歩かせず、古い観測で押下を開始しない |
| 位置変更が不可能 | 巡回側が理由を返し保留 | 腰や腕で無理に吸収するというfallbackを契約に埋め込まない |
| 開始前に中止 | 依頼の実行権限を失効→開始しない | 遅れて届いた実行可能応答を無視できる |
| 動作中に中止 | 移動を引き続き禁止→作業側が中止結果と復帰状態を報告→保留 | 中止要求の送信を復帰完了と扱わない |
| 反応が不明 | 確認不明と復帰状態を別々に報告→保留 | 二重押下や意図しない操作の繰り返しを避ける |
| センサー・通信・制御異常 | 移動と新規作業を禁止→状態不明を保持→人が原因を確認 | タイムアウトで排他を自動解除しない |
| 以前の完了通知が到着 | 依頼IDと許可の世代が違えば状態を変えない | 前回の成功で現在の中止・異常を解除しない |

押下側が「右腕のみ」「腰と腕」「別の手先・認識方式」に置き換わっても、上表の情報と責任は変わらない。
立位安定性の判定や異常時の上半身制御は、各作業実装が実機で検証して保証する内容となる。

## 計測後に確定する内容

到着分布と計測精度を得てから、押下側へ要求する補正範囲、navigation側へ戻す位置ずれ、
再接近の回数・候補・時間上限、停止判定の運用閾値を検討する。
腰のyaw/pitch/rollの採否や角度上限は、押下機構の比較評価で決める。
今回の解析の閾値や合成データのずれを、実機制御の仕様へそのまま転用しない。
