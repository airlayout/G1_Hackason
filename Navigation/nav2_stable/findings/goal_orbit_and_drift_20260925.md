# ゴールに着いたのに止まれず、回り続けて自己位置を壊した（2026-09-25 実機・2回目の走行）

**巡回の 2 回目で、機体は p2 に着いたのに到達と判定されず、180 秒間その場で回り続けた。
その旋回で内蔵SLAM がドリフトし、最終的に自己位置が 10.8m ずれた。**

記録: `runs/20260925_194258_nav2`（PC2）。解析用のコピーと読み取りスクリプトは
`_local/logs_20260925/`（`run2.db3` / `read_rosout.py` / `exact.py` ほか）。

⚠️ **`/tmp/nav_launch.log` は PC2 の再起動で失われた。** 記録に `/rosout` が
入っていたので中身は復元できた。**`/tmp` のログは当てにしないこと。**

## 1. 何が起きたか

| 時刻(PC2) | できごと |
|---|---|
| 20:56:31 | 巡回開始（p2 へ。3.0m 手前から） |
| 20:56:51 | **p2 に到達**（距離 0.167m）。以降 180 秒、半径 0.35m から出ていない |
| 〜20:59:31 | 位置と向きが**一度も同時に許容内にならず**、巡回ノードのタイムアウト |
| 20:59:33 | 再試行。ここで `collision ahead` が **370 回**噴出 |
| 21:00:34 | 人が pause。**機体は実際には見当違いの場所におり、リモコンで p2 まで運んだ** |

## 2. 数字

775 サンプル（20:56:31〜20:59:32、実効 4.3Hz）を、実際の `map→odom`
（`tf_static` から取得: `(5.600,-1.450) yaw=-9.00°`）で評価した。

```
p2 までの最小距離 = 0.009 m   （許容 0.20m）→ 231 件が許容内
向き誤差の最小    = 0.6°      （許容 11.5°）→   8 件が許容内
**両方を同時に満たしたサンプル = 0 件**

位置が許容内だった 231 件 → 向きの誤差は 最小 33.9° / 中央 136.2° / 最大 177.4°
向きが許容内だった   8 件 → 距離は     最小 0.311m / 中央 0.351m / 最大 0.377m
```

**位置が合うときは必ず後ろを向き、向きが合うのは必ず 0.35m 離れた場所。**
偶然ではなく、ゴールのまわりを回る安定した周期運動になっていた。

指令（`/cmd_vel_smoothed`）:

```
vx : 最小 +0.000 / 最大 +0.280 / 平均 +0.074   **負は 0 回**（後退していない）
wz : ±0.300（上限に張り付き）  **符号反転 33 回 / 2.5分**
20:58:45〜20:59:04 は wz=+0.300 のまま**まるまる 1 周**した
```

## 3. 原因

`RegulatedPurePursuitController` の設定:

```yaml
use_rotate_to_heading: true
rotate_to_heading_min_angle: 0.785   # 45°
min_lookahead_dist: 0.3
```

ゴールまで数 cm になると、経路上の追従点（carrot）は実質ゴールそのものになる。
**数 cm 先の点への方位は、わずかな横ずれで符号が反転する。**
その方位差が 45° を超えると「その場旋回」に切り替わり、**比例制御ではなく
上限の wz で回る**ので必ず行き過ぎる。行き過ぎると方位差の符号が反転し、逆へ回る。

さらに **p2 は角**である。p1→p2 は東向き、p2→p3 は南向きなので、`--face-next`
で入れた `yaw_deg: -91°` は**到着時に約 110° のその場旋回**を要求していた。
歩行機は旋回中に位置がずれるため、回れば位置が外れ、位置を直せば向きが外れる。

⚠️ **`SimpleGoalChecker` は位置と向きを「同時に」要求する。** これが決定打。

## 4. 自己位置が壊れた

| | |
|---|---|
| 2回目の §7 と、1回目（目視確認済み・一周成功）の姿勢の差 | **0.31m / 4.3°** ＝ 出発時は合っていた |
| ぐるぐるしていた 2分35秒 | odom 上は 0.4m 四方から出ていないのに **11.85m 歩いている** |
| 最後（人がリモコンで p2 まで運んで停止） | 推定は `map(-1.67,-3.83)`、実際は p2 `(9.02,-2.06)` → **10.8m ずれ** |
| odom の飛び | **0 件**（1サンプルで 0.15m 以上動いた回数）。滑らかに壊れている |

**出発時は合っていて、走行中にずれが育った。**
最有力の原因は**その場旋回による内蔵SLAM のドリフト**。既知の実測値
「5m 歩いて 7cm」は**直進時のもの**で、旋回時は測っていない。

⚠️ **確証は無い。** この日の記録は `diag` プロファイル（19 トピック）で
**点群が入っていないため、オフラインで自己位置を再計算できない。**
**次からは点群を含めて録るか、`map2odom_ctl.sh observe` を併走させること。**

📌 **2つの問題は繋がっている。**

```
ゴール判定が位置と向きを同時に要求 → 収束せず回り続ける
    → 内蔵SLAM がドリフト → 自己位置が壊れる → 全く違う場所へ歩く
```

**回り続ける不具合は、時間を浪費するだけでなく自己位置を破壊する。**

## 5. 対処（2026-09-25 に入れた。⚠️ **実機で未検証**）

記録から許容値を振って、到達までの時間を計算した:

| xy許容 | yaw許容 | 到達まで | 該当サンプル |
|---|---|---|---|
| 0.20m | 0.20rad (11.5°) | **到達せず** | 0 件 ← **これが元の値** |
| 0.40m | 0.20rad | 147.6 秒 | 8 件 |
| 0.20m | 1.00rad (57°) | 20.3 秒 | 8 件 |
| **0.30m** | **1.00rad** | **20.3 秒** | **18 件** ← 採用 |
| 0.30m | 1.57rad (90°) | 19.0 秒 | 50 件 |

**効いているのは向きの許容値。** 位置を 0.20→0.40m に倍にしても 147 秒かかる。

→ `config/nav2_params.yaml` の `goal_checker` を
**`xy_goal_tolerance: 0.30` / `yaw_goal_tolerance: 1.00`** にした。

⚠️ **駄目だったときの落とし先**（この順で）:

1. `yaw_goal_tolerance: 1.57`（90°）
2. **各点の向き指定自体をやめる**（`yaw_goal_tolerance: 3.14`）。
   位置に入った瞬間に到達となり、向きは着いたときのまま。
   **次の区間が始まれば RPP の `use_rotate_to_heading` がその場で回す。**
   この旋回は**ゴール判定を通らない**（経路方向との差が 45° 以内で抜ける）ので
   無限ループにならない。つまり「曲がるタイミングが到着時から出発時へ移る」だけ。
3. 向きが本当に要る点は、**到着後に別動作で回す**。
   ⚠️ **Nav2 のゴールに向きを含めてはいけない** — 「位置と向きを同時に」が原因だから。

## 6. AMCL は使えない（検討した結果）

- **`/scan`(LaserScan) が実機に存在しない。** G1 が出すのは 3D 点群だけ
  （`global_costmap` から `obstacle_layer` を外してあるのも同じ理由）
- D-19 のとおり **MID-360 の非反復走査・3D 特性が AMCL に合わない**

代わりに `tools/map_localizer.py`（3D 点群のまま照合し `map→odom` を出し続ける）が
**実装済みだが実機で未使用**。⚠️ ただし **AMCL も map_localizer も「地図が現況と
合っている」ことが前提**で、この日の一致率は 50cm以内 **47%** しかない。
**地図の取り直しのほうが根本。**

## 7. 手順の抜け（再発防止）

- `g1up.sh` は §7 の一致率が **50cm以内 80% 未満**なら
  「**RViz での目視確認を必ず行うこと**」と警告する。
  **2回目は `g1up.sh` を通さず `find_map_offset.py` を直接叩いたので、
  この警告が出ず、目視確認も飛ばした。**（1回目は確認して「あっている」を得ていた）
- ⚠️ **§7 の値が 3 回とも同一でも、正しさの証拠にはならない。**
  大域探索が安定して誤った山を掴むことはある。**目視確認が唯一の砦。**
- `collision ahead` 対策の costmap 消去ループを**止めたまま巡回を start した**。
  再試行時の 370 回はこれが原因の可能性が高い。**start の前に消去を確認すること。**
