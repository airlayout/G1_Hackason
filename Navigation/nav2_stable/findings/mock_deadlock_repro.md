# 旋回デッドロックをモックで再現し、対処を検証した（2026-09-16、実機不要）

2026-09-15 の実機セッションで、Nav2 の経路追従が**きっかり 10 秒ごとに abort** し、
機体が一歩も動かない現象に3回遭遇した（Planning.md A-10n）。その原因の特定と
対処の妥当性を、**実機を使わずに**確認した。

再現手順: `./tools/mock_deadlock_test.sh old` / `... new`

---

## 1. 何が起きていたか

`RegulatedPurePursuitController` の rotate-to-heading は、**実測角速度（odom）を基準に**
加速度制限をかける。

```
指令 = 実測角速度 + max_angular_accel × dt
```

二足は指令が小さすぎると**歩容が成立せず、まったく動かない**
（U-12 実測: `vx=0.1` は不成立 / `0.2` は歩くが方向が定まらない / `0.3` で実用的。
角速度は `0.02` で不動、`0.3` で回る）。したがって:

```
1周期目: 0 + 0.40 × 0.05 = 0.02 rad/s → 歩容の閾値未満 → 回らない → 実測は 0 のまま
2周期目: 0 + 0.40 × 0.05 = 0.02 rad/s → 以下同じ
```

**指令が 1 周期ぶんの増分から永久に増えない。** 実機では `wz=-0.02` が **2,363 周期**
続き、機体は **4mm** も動かなかった。

そして `SimpleProgressChecker` は**並進しか見ない**ので、その場旋回中は
`required_movement_radius: 0.05` を満たせず、`movement_time_allowance: 10.0` で
**10 秒ちょうどに abort** する。これが「10秒ごとの abort」の正体だった。

📌 **これは「加速度制限」と「最小作動閾値を持つ二足」の構造的な非互換**であり、
機体の不調でも配線の誤りでもない。

---

## 2. モックで再現できる理由

必要なのは**物理ではなくフィードバックの構造**だけ。モック（`g1_sdk_bridge_mock_server`）は
指令を積分するだけの替え玉だが、そこに「**指令が閾値未満なら積分しない**」性質を
足せば、上のループがそのまま再現する。

⚠️ **MuJoCo は使えない。** `unitree_mujoco` は low-level 専用で、`SetVelocity` の
高レベル歩行 API が存在しない（U-05）。我々の経路そのものが通らない。
Isaac Sim は統合が一仕事（Phase 5、任意）。

実装: `SdkBridgeConfig::gait_min_vx` / `gait_min_omega`（**既定 0 = 無効。
実機の挙動は一切変わらない**）。モック側は `--like-g1` で実機に近い値
（vx 0.2 / omega 0.15）をまとめて入れられる。

## 3. 結果

| | 旧設定（0.40 + SimpleProgressChecker） | 新設定（6.0 + PoseProgressChecker） |
|---|---|---|
| `/cmd_vel_smoothed` の wz | **0.020 で頭打ち**（86件すべて同じ） | **0.300**（369件。0.24→0.26→0.28→0.30 と立ち上がる） |
| 60 秒後の姿勢 | **(-3.000, -4.000) / 0.000°** ＝ 1mm も動かない | **(-2.944, -2.129) / 5.69°** ＝ 1.88m 移動 |
| 結末 | `follow_path` abort → `spin` → 繰り返し | **`Reached the goal!` / `Goal succeeded`** |

📌 **`wz = 0.020` は実機で観測した値と完全に一致する。** 原因の特定が正しいことの裏付け。

---

## 4. ⚠️ これで言えないこと

- モックに物理は無い。閾値を**階段関数**で模しただけで、実機の閾値近傍の挙動は違う
- **実機の旋回の作動閾値は未知。** `0.02` で動かず `0.3` で動いた（U-11）ことしか
  分かっていない。**真の閾値が 0.3 より上なら、`max_angular_accel: 6.0` でも足りない**
  （6.0 × 0.05 = 0.30 が1周期ぶんの指令になるため）
- そのときは `rotate_to_heading_angular_vel` を明示するか、`max_angular_accel` を
  さらに上げる（`10.0` なら1周期で 0.5）

📌 `g1_slam_odom_tf.py` は内蔵SLAM の `twist` をそのまま中継している
（`:350`）ので、**回り出しさえすれば実測角速度が入り、以後は正常なフィードバックに戻る**。
問題は「最初の一歩」だけ。

## 5. 途中で踏んだもの（3件）

| # | 事象 | 対処 |
|---|---|---|
| ① | **ホストでビルドしたバイナリがコンテナで動かない**（`GLIBCXX_3.4.32 not found`）。「起動したつもりで起動していない」＝ TF が出ないだけ、という分かりにくい形で出る。**2026-09-16 午前の「モックで起動確認した」という報告は、この状態だった** | モックは**コンテナ内でビルドする**（`mock_deadlock_test.sh` が自動でやる） |
| ② | launch 引数 `bridge_sock_dir` の既定を `/run/g1_bridge` 固定にしたら、**モック構成が無言で壊れた**。モックは `/tmp/g1_bridge` に作るので繋がらず、状態が来ない → TF が出ない → `controller_server` が activate できない | **backend で既定を変える**（real→`/run`、mock→`/tmp`）。修正済み |
| ③ | モックでは **`heartbeat_required:=false` が必須**。既定 true だと `enable_navigation` が拒否され、`cmd_router` はゼロしか転送しないのでモックが動かない | **設計どおりの正しい動作**。モック手順に明記した |
