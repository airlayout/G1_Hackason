# 失敗ログ

このフォルダでの開発中に実際に起きた失敗と、その原因・反省・再発防止策を記録する。
新しい失敗が起きたら、下のテンプレートに沿って追記する。

## テンプレート

```
## YYYY-MM-DD: 失敗の一言タイトル

**何が起きたか**
（観測された事実。憶測ではなく実際に見えたことを書く）

**原因**
（コード上・手順上の根本原因）

**反省**
（なぜ事前に気づけなかったか。見落としていた前提は何か）

**再発防止策**
（実際にコード/手順をどう変えたか）
```

## 2026-09-02: 自作の運動学モックが「歩けない経路」を1件も見つけられなかった

**何が起きたか**

Phase 3 まで、sim の相手（`sim/fake_service.py`）は「目標へ等速直線で進む」自作の
運動学モデルだった。この sim では四隅巡回・人が横切る・居座る障害物・通路封鎖の
4 シナリオすべてが期待どおりに動き、「Phase 3 完了」としていた。

Phase 3.5 で同じシナリオを **MuJoCo + 学習済み歩行ポリシー**に差し替えたところ、
その場で 2 件の不具合が出た。

1. 迂回で地図へ書き込んだ仮の障害物（半径 1.0m）の中に、17 秒後の機体自身が
   0.95m まで入り込み、「出発点が障害物の中にある」で経路を引けず巡回が止まった
2. `nav/occupancy.py` が `pyproject.toml` に無い `open3d` をモジュール先頭で
   import していた。venv にたまたま入っていたので動いていただけだった

**原因**

自作の運動学モデルは、計画した直線を**そのままなぞる**。
歩容の揺れも定位のずれも存在しないので、「経路が引けた」＝「歩ける」になる。
検証したつもりで、実際には `nav/route.py` の出力を `nav/route.py` の基準で
検算していただけだった。

**反省**

「sim で 4 シナリオ通った」を根拠に Phase 3 完了と書いたが、
その sim が何を検証**できない**かを書いていなかった。
差し替えるまで、自分が何を確かめていないのか自覚が無かった。

**再発防止策**

- 自作の運動学モックを削除し、Unitree 公式の学習済みポリシー + MuJoCo に置き換えた。
  以後、sim は常に本物の物理で歩く（`--mock` のような抜け道を作らない）
- 地図と MuJoCo の世界を `sim/rooms.py` が 1 つの寸法から生成するようにした。
  食い違いが原理的に起きない
- `nav/mission.py` は迂回の推定を地図へ書き込まず、円の一覧として持つようにした。
  実測の地図（`_base_grid`）は読み取り専用で、足元のぶんだけ憶測の層に穴を空ける
- `Navigation/README.md` の実測表に「転倒 0 回」「骨盤高さ 0.77〜0.78m 維持」を載せ、
  **歩けたかどうかが結果に出る**ようにした
- `tests/run_tests.sh` は sim の依存が無ければ 18 件を skip し、その件数を出力に残す。
  CI が緑でも歩行は検証されていないことが見えるようにした
