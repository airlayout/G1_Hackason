01　当日の 3 分チェック

最後に 「今すぐ見せられるのは n / 4 です」 と「次にやること」が出る。 そこに書いてあることだけやればよい。

02　機材と、どれがどこで動くか

項目3 は PC の中だけで完結する。実機に繋がるのは項目2 のライブと項目4 だけ。

03　項目3 — Isaac Sim で Nav2 走行 実測済み

実機は要らない。実測した部屋（UiS_room_v3）を再現したシーンの中で、RViz2 でクリックした場所まで G1 が歩く。

  1. 起動する

    bash Demo/02_isaac_nav2.sh

    3〜6 分かかる。 Isaac Sim の窓が開いてもまだ触らないこと。 [OK] Nav2 が起動しました と [OK] RViz2 を開きました が出たら準備完了。

  2. ゴールを置く

    RViz2（画面の右半分）の上のツールバーで 「2D Goal Pose」 を選び、 地図の上の行かせたい場所をドラッグする。矢印の向きが到着したときの向きになる。

    押してはいけない

    「2D Pose Estimate」は絶対に押さない。 この地図は原点がずれているので、 クリックすると自己位置が大きく飛ぶ（実測で位置 31 m・向き 179 度）。 初期姿勢は起動時に自動で入っている。

  3. 歩くのを見せる

    左の Isaac Sim で G1 が歩く。RViz2 の「Navigation 2」パネルに Feedback: reached と Recoveries: 0 が出れば成功。

  4. 止める

    起動したターミナルで Ctrl-C。Isaac Sim も RViz2 もまとめて止まる。

見せる前に知っておくこと

G1 は指令ゼロでも漂流する。 Isaac Sim の中で -x 方向へ 3.4 cm/s ほど動くので、 起動を待っている 3〜6 分のあいだに 1.7〜2.3 m 移動している。故障ではない。 初期位置 (6.55, -0.78) は「立たせたい場所」ではなく 「漂流したあとの着地点」で選んである。この値を変えないこと。

04　項目2 — LiDAR で計測

実機があればライブ、無ければ記録の再生。引数なしで叩けば自動で切り替わる。

bash Demo/01_lidar.sh # 実機が居れば live、居なければ replay bash Demo/01_lidar.sh replay # 記録の再生を明示（実機不要） bash Demo/01_lidar.sh live # ライブを明示（実機が要る）

再生 実測済み

2026-09-06 に UiS_room_v3 で録った 3.0 GB・136,047 メッセージ。 RViz2 の左のリストで 「生の LiDAR」にチェックを入れると 1 スキャンぶんの生の点も見える。

ただし記録に /tf が入っていないので、生の点群は原点に貼り付いて見える。故障ではない。

ライブ 未検証

G1 が既に配信している点群を購読するだけなので、ロボット内部と競合しない。

ただし Unitree の DDS は ROS 2 の type hash を載せない。Humble では 31 fps で出せた実績があるが、 Jazzy では未検証。先に bash Mapping/real/ubuntu/check_lidar.sh で型が解決できるか見ること。

記録がデモ機に無いとき

Mac の「リモートログイン」が既定で無効なので、そのままだと繋がらない。 繋がらなければ Mac 側から押すコマンドが印字されるので、それを Mac で打つ。

この記録は Jazzy でそのままでは再生できなかった

ここは自動で直るので当日は意識しなくてよいが、同じ症状に当たったときのために残しておく。

06　止め方

普段は各スクリプトで Ctrl-C。ターミナルを閉じてしまったときだけ下を使う。

bash Demo/stop.sh
やってはいけない

手で kill や pkill を打たないこと。 止める signal は送る先で逆になるうえ、pgrep -f は 自分自身と bash -c のラッパにもマッチする。 除外を忘れて呼び出し元の ssh セッションごと殺したことが 2 回ある。

07　症状 → 原因

当日その場で引く表。

症状原因やること
RViz2 に地図は出るが G1 が動かない 「2D Pose Estimate」を押して自己位置が飛んだ 止めて起動し直す。Pose Estimate は使わない
起動待ちのあいだに G1 が壁に埋まった 漂流（-x へ 3.4 cm/s）。初期位置を変えていないか SPAWN_X/Y を 6.55 / -0.78 に戻す
ros2 bag info は通るのに play が落ちる Humble で録った db3 に metadata テーブルが無い python3 Mapping/real/ubuntu/repair_bag_for_jazzy.py <bag> --apply
LiDAR のトピックが見えない ros2 daemon が古い DDS 設定のグラフを返している --no-daemon を付ける（hz だけは非対応）
点群が RViz2 に出ない ROS_DOMAIN_ID の食い違い 実機の購読は 0、それ以外は 42
Isaac Sim が残って次の起動が壊れる 孤児プロセスが TF を二重配信している bash Demo/stop.sh（手で kill しない）
sudo のパスワードが打てない ssh 越し／VSCode の統合ターミナル デモ機のターミナルで直接打つ
Mac から記録を押す rsync が黙って終わる macOS の rsync は openrsync。--info=progress2 が無い そのオプションを外す

08　中身（触る人向け）

Demo/ は入口だけ。実装は領域フォルダが持つ。

崩してはいけない約束

  • Demo/ は入口だけ。 実装は領域フォルダが持つ（既存の Mapping/ Navigation/ Perception/ の並びを崩さないため）
  • 止め方を書き直さない。 IsaacSim_Env/stop_nav2.sh が signal の向きを知っている
  • キットが潰した落とし穴を書き直さない。 DoF 自動判定・指令トピック自動選択・ 腕速度の安全パッチは Teleop/vendor/g1-starter-kit/ に既にある

コードを直すときに踏む罠

書き方何が起きるか
$(grep -c … || echo 0) 0 件のとき grep は「0」を印字したうえで exit 1 を返すので "0\n0" になり、 [ -gt ] が integer expression expected で落ちる。代入の失敗で受けること
grep -q（pipefail 下） 見つかった時点でパイプ元を SIGPIPE で殺す。合格側の経路だけ落ちるので気づきにくい
pgrep -af / pkill -f 自分自身と bash -c のラッパにマッチする。呼び出し元の ssh セッションごと死ぬ
いきなり kill -9 RViz2 を強制終了すると apport がクラッシュとして拾いに来て、ゾンビと apport が残る。 SIGINT → SIGTERM → SIGKILL の順に上げる
$VAR の直後に全角文字 変数名の一部と解釈されうる。${VAR} で囲むか半角空白を空ける
ping で機器の生死を見る 「コマンドが無い」と「届かない」が同じ NG になる。lib.sh の tcp_probe（/dev/tcp）を使う
どれも実際に踏んだもの。消さないこと。

設定を足すとき

Demo/lib.sh の 1 箇所にだけ書く。 値は Teleop/config/g1.env.omen から読んでいるので二重に持たない。 デモ機ごとの上書きは Demo/demo.env（git では追跡していない）。
