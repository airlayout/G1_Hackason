# スクリプトの作り方の方針（ユーザーの考え。未検証の仮説として扱う）

## 毎回の処理と、その日に 1 回の前提を分ける

- **日付**: 2026-10-22
- **プロジェクト**: G1 ボタン押し（`real/auto_press.py`）
- **前提バージョン**: —
- **状況**: 事前確認のあと Enter なしで最後まで押すスクリプトに、最初は頭カメラの向き（深度から床・机の面を求める計算）や
  机の箱の日付など、すべての確認を押すたびに入れていた
- **原因（ユーザーの指摘）**: 押すたびに流れる処理に、その日のうちに 1 度測ればわかることまで入っていた
- **対処**: 押すたびのスクリプトには、そのつど変わりうる確認（モーションコントローラ、立っているか、画像が止まっていないか、
  ボタンならモータの mode）だけを入れる。首の傾き（頭カメラの向き）・机の箱・接続などは、その前の前提として先に行う
  （`real/REAL_DAY_PROCEDURE.md` の「Enter なしで最後まで流す」）
- **教訓**: 繰り返し実行するスクリプトに確認を足すときは、「その値は実行のたびに変わりうるか」で、毎回の確認か前提かを分ける。
  押す側がすでに確かめていることは、重ねて確かめない
- **追記（2026-11-04）**: 頭カメラの向きは、前提から毎回の確認に移した（`auto_press.py` の事前確認「頭カメラの向き」）。
  2026-11-03 に、G1 をつなぎ直すたびに首の向きがずれた（ラボで 61.2°、エレベーターで 64.4°。直すと 51〜54°）ため、
  「実行のたびに変わりうる」側だと分かった。同じ基準で分け直しただけで、方針そのものは変えていない。
  測るのは 1 フレーム 0.2 秒ほどで、押すたびでも重くない。床が広く写る所で首を直す前後を測るのは、これまでどおり
  その日の最初に `check_head_tilt.py` で行う
