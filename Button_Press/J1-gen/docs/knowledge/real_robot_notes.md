# 実機（G1・PC2・カメラ）と開発環境で分かったこと

班で共有するための、短い知識のまとめ。手順は `real/REAL_DAY_PROCEDURE.md`、日ごとの記録は `real/DAILY_LOG_*.md`、
シミュレーションでの結果は `README.md` の「エレベーターの呼びボタン」を参照。

## G1・PC2

- **無線では lowstate も腕の指令も届かない。** G1 の DDS は中の有線（192.168.123.x）だけを流れる。無線（PC2 の
  192.168.0.82、DHCP）でできるのはカメラ（配信・受信・YOLO・収録）だけ。腕と lowstate は有線のラボ PC で（2026-09-29、10-14）
- **`run_g1_server.py` は起動時に `MotionSwitcherClient.ReleaseMode()` を実行し、歩行の制御を解除する。** 立っているときに
  起動すると倒れるおそれがある（`Perception/real/README.md`）。lowstate を無線に中継する目的では使わない
- PC2 では Unitree の `videohub_pc4 /dev/video4`（頭のカラー）と **`videohub_pc4_chest /dev/video10`（胸のカメラ）** が
  root で常駐している（2026-10-14）。止めない
- PC2 の `lsusb` は D435i（`8086:0b3a`）を「Intel Corp. 4-Port USB 3.0 Hub」と表示する。名前ではなく ID で探す

## 頭のカメラ（RGB-D）

- **実機の頭カメラは、立った状態で水平から 71° 下を向いている**（URDF の 47.6° より 24° 下。2026-10-21、床と机の面・
  FK の指先の投影の両方で確認）。実機用のカメラ設定（`configs/camera.yaml` の `head_camera_mount`）で上書きしている。
  天板の高さで見えるのは pelvis から前 約 40 cm まで。**床から 1.03〜1.10 m のエレベーターのボタンは、押せる距離では写らない**
  （`real/DAILY_LOG_20261021_labpc.md`）
- **videohub のカラーが古い画像のまま止まることがある**（2026-10-21）。深度は動くので、位置合わせがずれて YOLO も外れる。
  配信サーバの起動し直し・USB の差し直しでは直らず、G1 の再起動で直った。配信を始めたら、カラーが動いているかを最初に見る
- videohub がカラーを使っていても、**深度だけなら RealSense から開ける**（USB のインタフェースが分かれている）。
  `rgbd_server.py --source videohub` は、カラーを videohub から受け取り、深度を自前でカラーに位置合わせする
- 2026-10-14 に実機で確かめた: 5 fps（`--max-fps 5`、無線）、カラー 640×360、内部パラメータ fx 454.2・fy 453.8・
  cx 318.6・cy 190.7、深度 → カラーの平行移動 [0.015, -0.0004, 0.0003] m。向き・色・輪郭の重なりは正しい。
  カラーと深度の撮った時刻の差 約 30 ms、位置合わせの計算 約 100 ms（PC2）、受信までの遅れ 約 170 ms
- 深度の画像に、値 0 の点が規則的に並ぶ（約 2.7%。640×480 → 640×360 に並べ直すときのすき間）。ボトル・ボタンは
  領域の中央値で深度を取るので影響しない
- `configs/localize.yaml` の深度の上限は 1.5 m。床に置いたボトル（1.59 m）は YOLO が見つけても位置が出ない
  （「有効な深度が 0 画素」）。腕が届く範囲（0.5 m 前後）で試す。机の上 0.60 m では確信度 0.83、5 枚のばらつき 3 mm 以内

## ラボのエレベーターの呼びボタン（2026-10-15、スマホの写真 5 枚。G1 のカメラではない）

- 黒い柱に、一般用の ↑↓ と、その下に車いす用の ↑↓ がある。**点灯すると、ボタンの縁の細い輪（青みがかった白）
  だけが光る**。面と矢印は変わらない。枠全体の明るさの平均では輪の光が薄まるので、点灯の確認は明るい部分で見る
  （README の「確かめる」）
- **YOLO** は 5 枚とも 4 つのボタンをすべて見つけた。向きは、消えているボタンでは正しく、点灯した ▼ を 3 枚中 2 枚で
  「up」と読み違えた（点灯したボタンを学習していない）。点灯の確認では枠の位置だけを使うので影響しない
- **classic** は、本物の線の矢印（↑↓）の向きを全部逆に読む（シミュレーションのボタンは塗りつぶした ▲▼）。▲▼ の組は
  上下の位置で決めるが、読んだ向きが並びと合わないと組として認めないので、見つけられない。**このエレベーターでは
  YOLO を使う**（`J1GEN_BUTTON_DETECTOR=yolo`）

## 開発環境

- **YOLO を使う評価をノート PC（WSL2）で並列に回すときは `--workers 4`。** 1 プロセス約 2.5 GB（YOLO なしは約 1.7 GB）。
  11 並列で WSL2 ごと落ちた（2026-10-12）
- **GPU が複数ある PC では、nvidia-smi と PyTorch で GPU の番号が逆になることがある。**
  `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=<nvidia-smi の番号> ... --device 0` で選ぶ。RTX 50 系は `cu128` の torch
- YOLO の最初の 1 回の推論は遅い（ノート PC の CPU で 1.1 秒、2 回目から約 0.17 秒）。実時間で動く模擬 G1・実機では
  その間ロボットが待つので、`YoloButtonDetector` は読み込み時に 1 回推論しておく

## シミュレーションの評価の読み方

- 評価環境は**ボタンが点灯した瞬間に試行を終える**ので、点灯したあとの動き（押し続ける・確かめる・腕を戻す）の問題は
  数字に出ない。点灯で終わらせない診断で確かめる（2026-10-14: 点灯後の押し込みで柱に 7〜22 N かかる配置があった。
  2026-10-15 に直した。次の項目）
- **かたい止まりに当たったら、目標を奥に置いたまま押し続けない。** 腕は弱い PD なので、押す力は「指令と実際の
  指先の差（遅れ）」で決まる。ボタンが底に着いたあとも面の 15 mm 奥を目標にすると、遅れが 26 mm まで増え、
  中心からずれた位置を押していた指先が横に滑って柱の穴の縁を 21.6 N で押した。遅れが 5 mm を超えたら止めて、
  実際の指先の 2 mm 先を押したまま保持する（最大 5.0 N に）。触れる前の遅れは評価環境で最大 1.9 mm
- 評価の接触力は「ロボットと壁・盤」だけで、**ロボット自身の体どうしの接触は入らない**。押す向きと逆にまっすぐ下がると、
  柱が近い（31 cm）とき 10 cm 以上で右の手首が胴体に入った。腕は来た経路を逆にたどって戻す
- realistic のカメラの取り付けのずれ（角度 最大約 ±1.5°）で、ボタンの位置の推定が押す向きに最大 19 mm ずれる。
  実機でも同じことが起きるので、段階4の較正（`configs/localize.yaml` の `offset_pelvis_m`。ボタンにも使われる）が大事
- **シミュレーションは腰（pelvis）を固定している**（J1-gen も Yada さんの評価環境も）。実機は足側のバランス制御が
  腰を動かすので、腕を伸ばしたときや押した反動で、測った対象の位置と腰の関係がずれる。どれだけずれるかは実機で測る:
  ボトルは全体をつなぐスクリプトが終わったときに表示する（`body_motion.csv`）、エレベーターは `J1GEN_BODY_LOG` を付けて
  動かし `real/body_motion.py` で読む（README の「押している間の体（pelvis）の動き」）。脚の関節角の FK で求めるので、
  新しいトピックは要らない

## 立つ位置（エレベーターの呼びボタン）

- **pelvis から柱の面まで 29〜40 cm、▲▼ の中点が体の中心から左右 6 cm 以内**に立たせる（シミュレーションで確かめた範囲、
  2026-10-15。README の「立つ位置」）。範囲の外なら、エージェントがどちらへ何 cm 動けばよいかをログに出す
- 遠すぎると、腕より先に**頭カメラの視野**で決まる: 41 cm 以上で高い ▲（床から 1.10 m）が画像の上に切れ、見つからない。
  近すぎると、腕が胴体に当たるか肘の範囲を超えて計画できない（27〜28 cm で起き始める）
- 実機のカメラの取り付け・ボタンの高さで変わるので、実機ではこの範囲の真ん中（32 cm 前後）から試す

## 立つ位置（ボトル）と、押し込みの止め方

- **押す点（ボトルの手前の面）まで 30〜40 cm、体の右 15〜25 cm、机の手前の縁まで 29 cm 以上**（シミュレーション、2026-10-15。
  README の「立つ位置（ボトル）」）。エレベーターと違い、近い側は**机の縁**で決まる（手を上げる途中で手首が縁に当たる）。
  机が高いほど縁から離れる必要がある。ボトルは机の縁の近くに置く
- 押し込みは、指令と実際の指先の差（遅れ）が 5 mm を超えたら止める（エレベーターと同じ）。止めないと、固い物では遅れが
  25 mm まで増え、反動で腰がねじれて安全確認で中止した。実機のボトルは柔らかいので、止まったときの押す力を実機で確かめる
- ボトルは、安全確認で中止すると、その場で止めて来た経路を逆にたどって開始姿勢へ戻ってから weight を下げる（2026-10-15 から。
  以前はその場で weight を下げ、腕がまっすぐ下がって机に当たった）。q や Ctrl+C でも戻る。**戻る途中が危ないと思ったら、
  もう一度 Ctrl+C**（戻らずにその場で weight を下げる）。さらに危なければ L2+B。エレベーター（Yada さんの `run_dds.py`）の
  Ctrl+C は、今までどおりその場で weight を下げる
