# 強化学習（PPO）でボトルを押す: 工夫したことと、難しかったこと

2026-11-01〜11-13 に、右腕 7 関節を PPO で動かして MuJoCo 上のボトルを押させた（`rl/`）。ここでいったん終わりにした。
経緯・数値・各版の結果は [../../reports/rl_press_log.md](../../reports/rl_press_log.md)、外の人向けの要約は
[../../reports/REPORT_rl_press.md](../../reports/REPORT_rl_press.md)。ここには、次に強化学習をやるときに使える教訓だけを書く。

## 成功率が高くても、判定の抜け穴を使っていることがある（v2: 成功 98% は見かけだけ）

- **日付**: 2026-11-01
- **プロジェクト**: G1 ボタン押し（Button_Press/J1-gen/rl）
- **前提バージョン**: MuJoCo 3.14.0、stable-baselines3（PPO、MLP [256, 256]）
- **状況**: 評価 50 配置で成功 49。報酬も上がっていた。ところが成功した瞬間を調べると、ボトルに触れていたのは指先ではなく、
  ハンドの当たり判定の箱の角（指先から約 50 mm）で、指先は面の 3〜21 mm 手前、指の向きは前方から 9〜37° 傾いていた
- **原因**: 成功の条件が「押す点の近く・押す力が範囲内」だけで、どこで押しても通った。当たり判定の箱は実物のハンドより大きい
- **対処**: 条件に「指先が面まで届く（押す点の x − 指先の x ≤ 3 mm）」「ボトルとの接触点が指先の近く（2 cm 以内）」を足した。評価に
  接触点・面までの距離の列を出した。接触点の許容を 1 cm にしなかったのは、ボトルが円柱で、面の端で押すと指先から約 17 mm 離れるため
- **教訓**: 成功率と報酬だけで判断しない。成功した瞬間の接触点・指先・面までの距離・力まで見る。当たり判定がメッシュより大きいときは特に

## 強打は、罰を強めても減らない。打ち切りで直る（v3b〜v5）

- **日付**: 2026-11-03
- **状況**: 成功 100%（v3b）でも、押す力の最大が 48.8 N（15 N 超が 3 配置）。「15 N を超えた分」の罰を 0.05 → 0.2 に強めても、
  15 N 超は 3 → 8 配置に増え、最大 50.7 N だった（v4）
- **原因**: 1 周期ずつ見ると、強打は接触した最初の 1 周期だけ（0 → 16〜20 → 9 → 4 N）。腕が上限の速さのまま、指先 11〜22 cm/s で当たる。
  毎周期の罰は、当たったあとにしかかからない
- **対処**: 押す力が 15 N を超えたら、その試行を失敗にして終わらせる（`force_abort_n`、−5）。接触の手前で減速するようになり、
  成功した回の押す力は全部 14.1 N 以下になった（v5）
- **教訓**: 「一瞬で起きる悪いこと」は、毎周期の罰では間に合わない。打ち切り（終わらせる）と大きな罰で、直前の動きを変えさせる

## 範囲を広げる前に、腕が届くかを計算する（v8 → v9）

- **日付**: 2026-11-03〜11-06
- **状況**: ボトルの置き方の範囲を広げていくと、成功が 92%（v7）→ 72%（v8）に下がり、続けても上がらなかった
- **原因**: 広げた範囲の約 23% は、腕を伸ばし切っても届かない位置だった。右肩から押す点までの距離で分けると、0.55 m 以上は 6 配置すべて失敗
  （腕の長さは、肩→肘 0.198 + 肘→手首 0.101 + 手首→指先 0.259 ≒ 0.557 m）
- **対処**: 押す点が右肩から半径 0.52 m（腕の 93%）の球の外なら、配置を引き直す（`scene.reach_radius_m`）。成功は 80〜84%
- **教訓**: 範囲を広げるときは、先に腕の届く範囲を計算する。届かない配置を学習と評価に入れると、成功率が頭打ちになり、
  方策が悪いのか配置が悪いのか分からなくなる

## 弱い配置は、学習のときだけ多く引く。評価と動画では偏らせない（v10: 80% → 88%）

- **日付**: 2026-11-06
- **状況**: 左右の端の成功が低く（左端 2/6、右 3/8）、中央は 35/36 だった
- **対処**: 学習のときだけ、端の配置を多く引く（`scene.edge_focus`。端は 30% → 約 65%）。評価と動画では確率を 0 にして、v9 と同じ 50 配置で比べる。
  端は右 3/8 → 7/8、左 2/6 → 5/6 に上がり、中央は 35/36 → 32/36 に少し下がった
- **つまずき**: 右か左かを引き直しのたびに決めると、球で落とされやすい右が減る（右 25%、左 36%）。引き直しの前に 1 回だけ決めて、右 33%・左 32% にした
- **教訓**: 配置の偏りを入れるときは、評価の配置が変わらないことを確かめる（確率 0 のとき乱数を余計に使わない）。引き直しがあるときは、偏りを決める位置に気をつける

## 「動かずに時間切れを待つ」方策（v1）

- **日付**: 2026-11-01
- **状況**: 23 万周期で成功 0。報酬の合計は上がっていたが、方策は動かなかった
- **原因**: 動きの急さの罰（action_rate −0.01）が、学習の初め（行動にばらつきを足して試す）だけで 1 エピソード約 −25 になり、
  届いた得（progress 10 で約 +4）や当たりの罰（−5）より大きかった。試すこと自体を罰していた
- **対処**: progress 50、action_rate −0.001
- **教訓**: 報酬の合計だけで判断せず、`progress.csv` の success・collision・timeout を見る。罰の係数は、学習の初めの試行での大きさを見積もってから決める

## 探す時間は、罰や条件の緩和では縮まなかった（v11、v12）。ここでやめた

- **日付**: 2026-11-06〜11-13
- **状況**: 成功する方策でも、押す点の 5 cm 以内に入ってから成功するまで、中央値 1.07 秒（最大 3.6 秒）かかる。実機では、指でなぞって探す動きに見える。
  時間の大半は、触れてから成功の条件（押す力、横 2 cm、0.3 秒続ける）を満たすまでの調整（触れる → 成功で 0.7 秒）。
  左端の配置は 1.8 秒と長い。失敗 6 件はすべて、5 cm 以内に入ったあとで失敗した（届かないのではなく、近くで決め切れない）
- **試したこと**:
  - v11: 5 cm 以内にいる間、毎周期 −0.04（1 秒で −2）、最初に触れたときの横のずれが 1 cm を超えた分を減点 → 探す時間 1.07 → 1.16 秒、成功 88 → 84%。**効かなかった**
  - v12: 成功の条件を緩める（押す力の下限 2 → 1 N、保持 0.3 → 0.1 秒）。罰は 0 に戻す → v10 の方策を新条件で測り直すと 0.89 秒、学習し直して 0.92 秒。
    成功 88%、当たりが 0 → 5 件に増えた。**ほとんど変わらなかった**
- **分かったこと**: 方策の「近づいて、触れてから合わせる」動き方は、報酬と成功条件の調整では変わりにくい
- **次にやるなら**: 今の計画器の動き（実機で 11/3 に 17 回中 15 回点灯）を土台にして、手前の姿勢まで計画器で運び、最後の小さな補正だけを方策が出す（residual RL）。
  作り直しは 1〜2 日の見込み。指の向きを固定する案（指を前方から 15° 以内）も未試験
- **教訓**:
  - 動き方（探す時間）の問題は、測ってから直す。`rl/search_time.py` で、5 cm 以内 → 成功、触れる → 成功などを出せる
  - 成功の条件を変えたときは、旧い方策も新条件で測り直して基準にする（条件の変更だけで 0.18 秒縮んだ）
  - 罰の効きは、大きさを成功の得・近づく加点（約 +20）と比べて見積もる。1 秒で −2 は小さすぎた

## 学習の環境で、はまったこと

- **日付**: 2026-11-01〜11-06
- **ノート PC（aarch64）の torch**: 小さなネットワークの計算を 2 スレッド以上で動かすと 3 倍遅い。`train.py` は既定で 1 スレッド。
  学習はメンバーの PC（CPU 12 並列で約 2,900 周期/秒）で行い、ノート PC は環境を作って確かめる用にした
- **`.pth` の書き方**: 場所だけを書くと、その場所の `.pth`（pin の cmeel.pth）が読まれない。`import site; site.addsitedir(...)` と書く
- **容量が 2 GB まで減った**: 絞らずに `run_all_tests.sh` を動かすと、Perception のテストが `pip install -r Perception/requirements.txt` で
  ultralytics・torch・nvidia（約 6.3 GB）を `~/.local` に入れる（2026-11-03）。Button_Press だけなら
  `CI_CHANGED_FILES="$(git diff --name-only)" bash scripts/ci/run_all_tests.sh`、強化学習のテストだけなら `~/rl_env/bin/python -m pytest tests/test_rl_env.py`。
  テストが依存を入れる場所は、動かす前に確かめる
- **`pkill -f` が自分のシェルを止める**: スクリプト名を `pkill -f` に渡すと、その名前を含む自分のコマンドまで止まる（2026-11-07）。
  PID を指定して止める。[shell_and_ssh.md](shell_and_ssh.md) も参照
- **学習は `nohup`（`setsid`）で動かす**: ssh を切っても止まらない。各回のあとに評価・動画・コピーまで自動で行うスクリプト（`chain_v*.sh`）にすると、待っている間に手が空く
