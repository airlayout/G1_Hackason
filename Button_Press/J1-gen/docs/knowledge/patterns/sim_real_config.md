# シミュレーションと実機で設定・データを分けるパターン

## 実機だけの補正は、実機用の設定ファイルに書く（シミュレーションと共用のファイルに書かない）

- **日付**: 2026-10-21
- **プロジェクト**: G1 ボタン押し（`configs/camera.yaml` の `head_camera_mount`・`depth_anchor`）
- **前提バージョン**: J1-gen の設定構成（`robot.yaml`・`localize.yaml` は MuJoCo と共用、`camera.yaml` / `camera_sim.yaml` は接続先ごと）
- **状況**: 実機の頭カメラの角度を直したいが、`robot.yaml` のカメラの値は MuJoCo のカメラの置き場所にも使われている。
  以前、重力補償の倍率を共用の `arm.yaml` に入れたら MuJoCo でも読まれ、補償が二重になってテスト 27 件が落ちた（2026-10-15）
- **対処**: 実機だけが読むファイル（接続先ごとに分かれた `camera.yaml`・`camera_wifi.yaml`）に上書きの項目を置き、実機用の
  スクリプトだけがそれを当てる。模擬ロボット用の `camera_sim.yaml` には書かない。有線と無線の 2 つが同じ値かをテストで確かめる
- **教訓**: 「どのファイルを誰が読むか」を確かめてから、補正を置く場所を決める。共用のファイルを実機に合わせて変えると、
  シミュレーションの結果が黙って変わる

## 実機の日のデータを、シミュレーションのテストが読んでいた

- **日付**: 2026-10-21
- **プロジェクト**: G1 ボタン押し（`configs/obstacles.yaml`、`common/pipeline_cli.py`）
- **前提バージョン**: 同上
- **状況**: 実機の机の箱を `configs/obstacles.yaml` に書いたら、シミュレーションのテスト 6 件が「手が箱に当たる」で落ちた
- **原因**: 全体をつなぐ処理が、シミュレーションでも既定で `obstacles.yaml` を読んでいた。それまでファイルが空だったので気づかなかった
- **対処**: シミュレーションの机を使うとき（`--sim-scene-obstacles`）は、実機の箱を明示したときだけ読む
- **教訓**: 「実機の日に書き込むファイル」は、空のうちはテストが通ってしまう。中身が入った状態でテストを回してから、実機の日を迎える

## 観測の受け渡しで値を入れ忘れても、既定値がもっともらしいと気づかない。記録の列がずっと同じ値でないかを見る

- **日付**: 2026-11-04
- **プロジェクト**: G1 ボタン押し（Yada さんの評価環境の実機用の口 `contest/robots/real_g1.py`）
- **前提バージョン**: 観測（`Observation`）の IMU の既定値は「直立」(1, 0, 0, 0)。MuJoCo の口は IMU を入れ、実機の口は入れていなかった
- **状況**: 推定トルクを足すときに実機の口を読んで気づいた。11/3 の body_log は 706 行すべて (1, 0, 0, 0)。エラーは出ず、「脚の FK の傾きと IMU の差が小さいので足は滑っていない」という結論が根拠のないまま書かれていた
- **原因**: 既定値が本物らしい値だったので、入れ忘れが正常に見えた。口ごとに値が入るかのテストが無かった
- **対処**: 実機の口で IMU を入れ（fd0d38d）、DDS・カメラにつながずに口を呼んで値が入るかを確かめるテストを足した（直す前は失敗する）。新しい項目 `tau_est` の既定は None にした
- **教訓**: センサーの値の既定は「無い」と分かる値にする。経路（シミュ・模擬・実機）ごとに値が入るかのテストを置く。記録から結論を出す前に、使う列が変化しているかを見る

## シミュレーションのゴムの手は白く、実機の手（と手袋）は黒い。画像で判定する処理の前提を分ける

- **日付**: 2026-11-10
- **プロジェクト**: G1 ボタン押し（押している間のランプの明るさ、`common/lamp_watch.py`）
- **前提バージョン**: c7371bf。`elevator.yaml` の `press.lit_watch.hand_mask`、`auto_press.py --hand-mask`
- **状況**: MuJoCo では白い手が枠に被さって明るく見え、触れる前に「点灯」と出た。手の範囲（メッシュを画像に写す）を除いて直したが、説明に「ゴムの手は白い」と書いていた。実機の手と手袋は黒い（ユーザーの指摘）
- **対処**: 手の画素を除くかを切り替えにし、シミュは除く（既定）、実機の入口 `auto_press.py` は除かない（`J1GEN_HAND_MASK=0`）。どちらでも、手の範囲と「ランプが手に隠れていない割合」は記録する
- **教訓**: シミュのモデルの色・材質は実機と同じとは限らない。見た目で判定する処理は、実機の見た目を確かめてから前提にし、シミュと実機で設定を分けられるようにする

## 評価環境（腰固定）で「歩いた」を試すときは、乗り場を歩いた分の逆にずらす。真値にも同じずらしを入れる（2026-11-11〜12）
- `sim/approach_sim.py`: 評価セット realistic の「立ち位置のずれ」（realism の stance_xy / stance_yaw）の口で、1 回分歩くたびに乗り場を
  逆に動かしてモデルを作り直す（Yada さんのファイルは変えていない）。乱しなしでは、乱しをすべて 0 にした realism を使い、関節の
  armature・摩擦は乱しなしのモデルと同じ値にそろえる
- 真値（本当の柱までの距離・ボタンの左右）は、実際に渡したずらしから計算する。評価セット自身のずらしを入れ忘れて、測った値の誤差を
  6.9 cm と大きく出しかけた（正しくは約 2 cm）
- 歩く量は偽物の足（`common/loco.py` の FakeLoco）。実機の歩きのばらつきは、実機日に `real/loco_pulse.py`・`real/loco_fit.py` で測って入れる
