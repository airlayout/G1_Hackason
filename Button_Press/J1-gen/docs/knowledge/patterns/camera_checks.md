# カメラの確かめ方のパターン

## 深度の床・机の面から、カメラの向き（pitch / roll）を求める。別の方法でも裏付ける

- **日付**: 2026-10-21
- **プロジェクト**: G1 ボタン押し（`common/head_tilt.py`、`real/check_head_tilt.py`）
- **前提バージョン**: RealSense D435i（深度をカラーに位置合わせ）、Pinocchio 4.1.0（腰の FK）
- **状況**: 体の座標で深度の点を見ると、床が約 30° 傾いて出た。IMU では骨盤は水平だった。カメラの取り付け角度（URDF の 47.6°）が
  実際と違うと疑った
- **原因**: 首が傾いていて、カメラが実際は 71° 下を向いていた
- **対処**:
  1. 深度の点群から平面を RANSAC で見つけ、「その平面が体の座標で水平になる」カメラの pitch / roll を探す。床と机の 2 枚で
     同じ値（70.65° / 71.45°）になれば信用する。真上の向きは IMU から取る
  2. 最初は範囲を決めた最小二乗で当てはめたが、机の脚やマットが混ざって床と机で答えが食い違った（内点 23%）。RANSAC で面の
     点を選び直すと揃った
  3. 別の方法で裏付けた: 関節角から分かる指先の位置（FK）を、候補の角度ごとに画像へ投影し、実際の指先に重なるかを見た
     （71° で重なり、47.6° では約 20 cm ずれた）
- **教訓**: 外部パラメータの推定は、独立した 2 つ以上の方法（面の水平・既知の点の投影・メジャー）で一致を確かめてから設定に入れる。
  面の当てはめは、外れ値に強い方法（RANSAC）で面の点を選んでから行う

## 画像が「止まっている」かは、2 枚の差がちょうど 0 かで分かる

- **日付**: 2026-10-21
- **プロジェクト**: G1 ボタン押し（`real/auto_press.py` の事前確認）
- **前提バージョン**: Unitree の videohub（PC2）から JPEG を受け取る配信
- **状況**: YOLO が対象を見つけず、深度と画像の位置がずれていた。原因は、カラー画像が古いまま更新されていないことだった
  （深度は更新されていた）
- **対処**: 時間をおいて受け取った 2 枚の差（画素の平均の絶対値）を見る。止まっていると 0.00、本物のカメラは静止した場面でも
  ノイズで 1 前後ある。ただし、シミュレーションの描画はノイズが無いので 0.00 になる（模擬ロボットではこの確認は通らない）
- **教訓**: 「エラーなしで古いデータを返し続ける」故障は、値がまったく変わらないことで見つけられる。深度と画像の重なりを
  重ねて見るのも早い（ずれていれば、どちらかが古い）
