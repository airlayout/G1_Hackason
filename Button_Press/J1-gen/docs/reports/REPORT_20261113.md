## 予想と違ったこと → 原因 → どう確かめたか → 何を変えたか

- **頭カメラが空の画像を返した** → 起動直後に Unitree の videohub がカメラをつかみ損ねたと思われる（確かめていない）
  → 3 分待っても空のまま。カメラ自体は USB で見えていた → ロボットを再起動して直った。2 回目の再起動ではすぐ動いた
- **押した力の推定が、空中（何にも当たらない）でも 6〜9 N** → 腕を前へ伸ばすほど増えるので、重力の計算と実機の差など、姿勢によるずれと思われる
  → 空中で 3 回（左 2・右 1）送って、どれも同じくらい出た → まだ直していない。直すまで、力の推定で「押せた」とは判断しない
- **regular mode にすると、腰の事前確認で止まった** → regular mode では立っているだけで腰 pitch が −3.3° になる（locked standing は −0.2°）
  → 流し続けていた記録で、モードを変えた瞬間に腰 pitch が変わったのを確かめた → 腰 pitch の上限だけ 3° → 6° にした（エレベーターも regular mode）
- **約 53 cm でもボタンが見えた** → 立つ位置の地図では 46 cm より遠いと ▲ が画像から出ると見込んでいた。今日の首は地図（53°）より上向き（50〜52°）
  → dry-run の画像で ▲▼ が両方入っていた → 地図の見直しは机の上で
- **柱の面までの距離が、床で首の向きを直すと 3〜7 cm 近く出た** → 床から求める首の向き（約 51°）と、ボタンの位置が合う向き（設計上の 47.6°）に約 3.4° の差がある
  → その日の収録から、同じ時刻のボタンからの距離（押して点灯した）と比べた → 直さない設定にする案。まだ変えていない
- **左腕・正面で押しても「立つ位置が範囲の外」と注意が出る** → 注意は右腕の範囲（右 14±2 cm）で出している → 計画は立って点灯した → 選んだ腕に合わせて直す（まだ）
- **指さしで腰が前へ倒れ、腰のずれの上限（5°）で止まった** → 腰は開始時の角度に保たせているが、保つ力（kp 60）が弱く、腕の重さで負けた
  → 収録で、ずれたのは腰 pitch だけ・骨盤は傾いていないのを確かめた → ハーネスがあるので上限を 8〜10° に上げて完走。腰を保つ kp を 120 にすると、ずれは半分以下になった → この動作だけ、上限の既定 8°・kp の既定 120 にした
- **左腕を送った 1 回目、動いたのに「動いていない気がする」** → 端末から切り離して起動したので、始まりの合図が無かった
  → 関節角の記録で動いていたのを確かめた → 送るコマンドは自分で打ち、Claude は dry-run までにした
