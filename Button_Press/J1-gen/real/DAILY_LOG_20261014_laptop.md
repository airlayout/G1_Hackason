## 2. 実機: 無線での RGB-D の取得（`rgbd_server.py --source videohub`、実機で初めて）

9 月 29 日の「次回やること」（手順書）の続き。カラーは Unitree の videohub から、深度は RealSense から直接取る。

### つなぎ方

- PC2（無線）: `192.168.0.82`（9 月 29 日と同じ）。ユーザー `unitree`
- PC2 には SSH の鍵を登録していない（`~/.ssh` は変えない）。PC2 のコマンドを Claude から実行するため、ユーザーが自分の
  ターミナルで 1 回だけパスワードを入れて、接続を使い回す形にした（パスワードはどこにも保存しない。3 時間で切れる）:

  ```bash
  ssh -fN -o ControlMaster=yes -o ControlPath=/tmp/ssh-pc2-tvdue -o ControlPersist=3h unitree@192.168.0.82
  ```

  Claude は `ssh -o ControlPath=/tmp/ssh-pc2-tvdue unitree@192.168.0.82 '<コマンド>'` で実行する。
  PC2 で実行してよいのは、カラー画像と深度の取得に関することだけ（ユーザーの許可の範囲）

### 無線でできないこと

- lowstate（関節の状態）は無線では届かない（G1 の DDS は中の有線のネットワーク 192.168.123.x だけ）。
  中継の `run_g1_server.py` は起動時に `MotionSwitcherClient.ReleaseMode()` で歩行の制御を解除し、
  立っていると倒れるおそれがあるので使わない（`Perception/real/README.md`）
- 腰の本当の角度での位置と、腕を動かす段階は、有線のラボ PC で行う（この日、ラボ PC 側で段階0 に進んだ）
- 無線で lowstate だけ読みたいなら、PC2 で DDS を受け取って ZMQ で送るだけの「読むだけの中継」を作る
  （約 1.5 時間の見積もり。PC2 のシステムの Python 3.8 に `unitree_sdk2py` があるかは未確認）
