# ボトルを倒す：実機日の手順書

机の手前の縁に置いた 500 mL の PET ボトル（水 50 mL ほど）を、立った状態の右腕で前方（机の奥）へ押して倒す。
実行するスクリプトは `real/knock_bottle.py`（`press_bottle.py` に `configs/knock.yaml` を重ねたもの）。
**有線のラボ PC で行う（無線では行わない）。** 全体の流れ・接続・ティーチングは [REAL_DAY_PROCEDURE.md](REAL_DAY_PROCEDURE.md) と同じなので、
ここには倒す動作に固有のことだけを書く。コマンドはリポジトリ直下（`G1_Hackason/`）で、1 行ずつ実行する。

最新の記録と再開手順: [DAILY_LOG_20261021_labpc.md](DAILY_LOG_20261021_labpc.md)（arm_sdk が効く・実機では `--gravity-scale 0.5`）。

## 先に知っておくこと（シミュレーションで分かったこと。README の「ボトルを倒す」）

- 水 50 mL は底にたまり、重心が底から約 3 cm まで下がる。**倒れきる角度は約 45°** で、手先は 9 cm 以上進める必要がある
  （押し込み 8 cm では最大 44° まで傾いて戻った）。
- **押す点が低いと、倒れずに机の上を滑る。** 底から約 8 cm（摩擦 0.4）より低いと滑る。
- 既定（押し込み 125 mm、測った面の点から 58 mm 上）は、MuJoCo で摩擦 0.3〜1.0・水 25〜100 mL のすべてで倒れた。
  ただし**窓が狭い**（上げ ± 5 mm で外れる）。摩擦 0.25 では滑る。
- **滑り止めのマットを敷くと窓が広がる**（摩擦 0.8 以上で、上げ 0〜40 mm・押し込み 100 mm でも倒れた）。**敷くことを勧める。**
- 押し込みの上限は約 13 cm（それ以上は腕が伸びきって計画できない）。
- ⚠️ 実機のハンドが当たる高さ・机の摩擦は未確認。**1 回目は、倒れなくてよい**（調整の材料を集める回）。

## 安全のルール

- **人が常にリモコンを持つ。緊急時は L2+B（ダンピング）。** 実行する人と、リモコンを持つ人は別にするとよい。
- ボトルは机の奥へ倒れる。**机の奥側に人・物を置かない。** ボトルが机から落ちても問題ない（安全面）が、落ちる先に人がいないこと。
- 腕を伸ばしきる動き（手先が体の前 44 cm 付近まで出る）。**最初は必ず dry-run で「届く」ことを確かめる。**
- 腰のずれ（既定 2.9°）で自動で中止し、腕は来た経路を逆にたどって戻る。戻る動きが危ないときは、もう一度 Ctrl+C（その場で weight を下げる）。
- プランB（lowcmd）は座った状態か吊り下げで。arm_sdk が効く機体では使わない。

## 準備

1. ターミナルを開くたびに最初に実行する（ラボ PC の古い CycloneDDS を避ける）:

   ```bash
   export CYCLONEDDS_HOME=$PWD/G1_HuggingFace/cyclonedds/install
   ```

2. 机の手前の縁にボトルを置く（縁から面まで 1 cm ほど）。**滑り止めのマット（ゴムシートなど）の上に置くと倒れやすい。**
   立つ位置は、押す点（ボトルの手前の面）まで 30〜40 cm、体の中心から右に 15〜25 cm、机の手前の縁まで 29 cm 以上（pelvis から）。
   範囲の外なら、スクリプトが「あと何 cm 動く」を出す。
3. 水を入れる（50 mL ほど。軽すぎ・重すぎは、あとで水の量を変えて試せる）。ラベル付きだと深度が取れやすい。透明な PET は深度が取れないことがある。
4. シミュレーションで環境を確かめておく（約 1 分。実機に何も送らない）:

   ```bash
   G1_HuggingFace/venv/bin/python Button_Press/J1-gen/sim/knock_bottle_sim.py
   ```

   最後に `ボトルの傾き: ... → 倒れた` と出れば OK。

## 手順

### 0. 接続と頭カメラの向き（毎回）

```bash
G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/check_connection.py --rgbd
```

- `mode_machine` = 5、RGB・深度が届くこと。
- **頭カメラの向きを確かめる**（首の傾きは日によって変わる。10/14 は約 45°、10/21 は首が傾いて約 71°）:

  ```bash
  G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/check_head_tilt.py --live --frames 5
  ```

  約 45° なら既定のまま。約 71° なら `configs/camera.yaml` の `head_camera_mount` のコメントを外す
  （首が傾いたままだとボトルの上が画像の外に出る。直してから測り直すほうがよい）。

### 1. 机の箱（衝突の確認用）

机が動いた、または初めてなら、立った状態の深度から箱を作る（先に 0 の頭カメラの確認）:

```bash
G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/make_table_boxes.py --live
```

出力（各 strip の手前の縁）と画像（上から見た図）を見て、体や下ろした手を覆っていなければ保存する:

```bash
G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/make_table_boxes.py --live --save
```

### 2. dry-run（何も送らない）

腕をカメラの視野から外し、ボトルが枠に入っていることを確かめる。

```bash
G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/knock_bottle.py --path arm_sdk --gravity-scale 0.5 --label knock_dry
```

見るところ:

- `対象（深度）: [x, y, z]` … x は 0.30〜0.40 付近。**z は「ボトルの底から約 14 cm 上」あたり**（机の天板 + 14 cm）。
  机の高さが分かっていれば、`z − 天板の高さ` が 12〜17 cm か確かめる。大きく外れていれば、深度の取り方（枠・ラベル）を疑う。
- `押す点のずらし [+0, +0, +58] mm` が含まれていること。
- 計画が立つこと。拒否されたら、表示された理由（届かない / ぶつかる / 作業空間の外）を見て、立つ位置を直す。
  `押し込みの直線の ... 点目で関節が 1 周期に ... rad 動く`（特異姿勢）が出たら、押し込みを短くする（`--depth-mm 110`）。
- 実機では押し込みの終わりが x = 0.44 前後。`configs/press.yaml` の `workspace`（右手の x は 0.65 まで）の内側であること。

### 3. 1 回目（確認モードで送る）

```bash
G1_HuggingFace/venv/bin/python Button_Press/J1-gen/real/knock_bottle.py --path arm_sdk --gravity-scale 0.5 --execute --label knock1
```

各段階で Enter。危なければ q か Ctrl+C、さらに危なければ L2+B。

- **押し込みの前に、手前の姿勢で手とボトルの位置関係を目で見る**（手が胴の上のほうに向いているか）。
- 押し込みは約 2.5 秒（5 cm/s で約 12 cm）。目で見て、ボトルが **倒れた / 滑った / 傾いて戻った / 触れなかった** のどれかを記録する。
- 倒れたかは、終わったあと（腕が開始姿勢へ戻ってから）**頭カメラの深度で自動判定**して、`[tip] 倒れたかの判定: ...` と出る
  （ボトルのいちばん高い点の高さが、押す前より何 cm 下がったか）。**自動判定も、必ず目で見た結果と照らし合わせる**（1 回目は特に）。
- 終了コード: **0 倒れた / 20 倒れなかった / 21 判定できない**（押す前の高さが求まらない、ボトルが見つからない（机から落ちた・視野の外）、
  深度が取れない）。dry-run は何も動かさないので、判定しない（0）。

### 4. 結果に応じて 1 つだけ変えて、繰り返す

一度に変えるのは 1 つだけ（原因が分からなくなるため）。

| 目で見た結果 | 考えられる原因 | 次に変えるもの |
|---|---|---|
| 倒れた | — | 同じ条件で数回繰り返し、毎回倒れるか見る（窓が狭い） |
| ボトルが滑った（傾かずに奥へ動いた） | 押す点が低い、机が滑りやすい | `--target-offset 0 0 0.068`（+10 mm）。または滑り止めのマットを敷く |
| 傾いたが倒れきらずに戻った | 押し込みが足りない、または押す点が高すぎる | `--depth-mm 135`（上限 140）。計画が拒否されたら、`--target-offset 0 0 0.048`（−10 mm） |
| 触れなかった / 空振り | 深度のずれ、体が逃げた（`body_motion` の「狙いのずれ」） | 手前の姿勢で指先と面の距離を見る。較正（段階4）を確かめる |
| 押している途中で止まった（`指先が進まなくなった`） | 押す速さで遅れが増えて `contact_stop` が働いた | `--speed-mm-s 30` に遅くする。ボトルが重すぎないか |
| ボトルが飛んだ | 速すぎる、または空に近く重心が高い | `--speed-mm-s 30`。水を増やす |
| 腰のずれで中止（終了コード 5） | 反力で上体が引っ張られた | 押し込みを短く、速さを遅く。しきい値は勝手に緩めない |

水の量・ボトルを変えるときは、変えた値を記録する。

### 5. 記録（全試行）

各回の記録は `_local/button_press/runs/<日時>_<ラベル>/`。次を書き留める（下の表の形）:

| 回 | ラベル | 摩擦（マット有無） | 水 mL | 押し込み mm | 上げ mm | 速さ mm/s | 結果 | メモ |
|---|---|---|---|---|---|---|---|---|

- 押し込みの結果の行（`指先が実際に進んだ ... mm（計画 ... mm）`）も書く。計画と大きく違えば、途中で止まった。
- 「体（pelvis）の動き」の「狙いのずれの最大」も書き留める。腕を伸ばしきるので、体が逃げて浅くしか押せていない可能性がある。
- 頭カメラの画像は `frames/` に残る（`approach`、`end`、`retreated`）。倒れたかの確認にも使える。

終了コード: 0 成功かつ倒れた / 20 成功したが倒れなかった / 21 成功したが倒れたかを判定できなかった / 2 目標を拒否 / 3 動いていない / 4 lowstate・相手・mode_machine・モータの問題 / 5 腰が倒れた / 130 中止

## 倒れ判定（自動）について

- 方法: ボトルを検出した枠の上端の帯の深度のうち、最も手前の画素（立っていればキャップ、寝ていれば遠いほうの端）の高さ（pelvis の z）を、
  押す前と押したあとで比べる。立っていれば約 20 cm、寝ていれば約 6.5 cm なので、差は約 13 cm。しきい値は `configs/knock.yaml` の
  `pipeline.tip_check`（6 cm 以上下がれば倒れた、3 cm 以内なら立っている）。
- 枠の縦横比は使わない。ボトルは机の奥へ倒れるので、寝ても画像の上では縦に長いまま見える。
- 判定できないとき（21）の原因: YOLO が寝たボトルを検出しない、PET が透明で深度が取れない、ボトルが机から落ちた・視野の外へ出た。
  どれかは、記録の `frames/*_tip_after_color.png`（押したあとの画像）で分かる。
- 実機の画像が溜まったら、検出と深度が取れているか、しきい値が合っているかを確かめる（`events.jsonl` の `tip_check` に高さが残る）。
