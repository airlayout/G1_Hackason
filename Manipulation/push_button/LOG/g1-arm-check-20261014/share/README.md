# G1 右腕の小動作確認ログ（2026-10-14）

## 結果

右肩を約12度前方へ上げて戻す試行を1回実施したが、保持段階で静止・姿勢監視の条件に該当し、中断した。腕の制御重みを解除した後、右肩は開始時との差約0.19度まで戻り、立位FSM 501を確認した。

**正常完了した試行としては扱わない。** 実際の最大挙上角と、中断を発生させた瞬間の測定値は記録できていない。動作を再試行していない。

## 実施条件と計画

- 機体：G1 29DoF（LowStateの `mode_machine=5`）。
- 実行場所：G1内蔵PC上。DDSは `eth0`、domain ID 0を使用。
- 実機側の確認：ユーザーが、安定した立位・右腕周囲の空き・リモコンによる即停止の準備ができていると回答した後に実行。
- 指令経路：Unitree SDKの `rt/arm_sdk`。右肩pitch（関節22）を開始角から `-12°` だけ変更し、他の腕関節は取得した開始姿勢を保持する計画。
- 制御周期：50Hz。肩・肘のkpは40、手首のkpは15、kdは1.5。脚・腰の目標値は設定していない。
- 計画：開始姿勢で制御重みを上げる2秒 → 挙上2秒 → 保持0.6秒 → 復帰2秒 → 静止待機0.5秒 → 腕の制御重みを下げる2秒。

## 同梱ファイルとログの由来

- `execution.log`：このチャットで取得した端末出力から転記したログ。標準出力と標準エラーは混在している。端末の入力エコーは省略し、出力本体を掲載している。
- `result.json`：保存済みの測定値と確認範囲。
- `probe_source.py`：今回実行した確認スクリプトの写し。通常実行は事前確認のみ。`--execute` は実機へ腕指令を送るため、ログ閲覧のために実行する必要はない。
- `SHA256SUMS.txt`：同梱4ファイルのSHA-256。

正確な試行開始・中断のタイムスタンプは記録していない。PCとG1の時計の同期も未確認であり、ログ中のプロセス開始時刻はG1側の表示をそのまま記載している。SSHパスワード・鍵・トークンは含めていない。

G1上の試行スクリプトは終了後に削除済み。この共有物は作業PCに保存した記録であり、作成にあたって実機の再動作は行っていない。
