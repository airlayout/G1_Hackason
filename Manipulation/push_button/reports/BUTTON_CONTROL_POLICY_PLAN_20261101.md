# ボタン版の同期送信と監視分離の実装プラン

## 状態と目的

2026年11月1日に合意した、帰宅後の実装再開用のプラン案。
この文書を保存する時点では、以下の変更は未実装。
基準コードは `a396f8e`（Add one-command robust elevator button press）。
既存のボタン用bash、設定例、テスト、手順書はこのコミットまでpush済み。

ボタン版も、実機で安定したボトル版と同じ同期送信に揃える。
そのうえで、下半身・腰の異常による停止と、腕の軌道ずれの記録を独立させる。
完成済みのボトル版の動作設定は変更しない。

現在は、腰の現在角保持と重力補償は両版で共通だが、軌道の送信方式が異なる。
ボトル版は検査した指令を1つずつ同期送信し、ボタン版は別スレッドが目標50Hzで最新目標を送信する。
ボタン版の実機押下による安定性は未確認。

## 採用する監視方針

| 検出した状態 | ボタン版の扱い |
| --- | --- |
| 脚の動き、腰・骨盤の姿勢変化 | 現在のボタン版の厳しい基準で停止する |
| 状態受信断、制御更新の途絶 | 現在の100ms基準を維持する |
| 腕の開始姿勢の小さな差、手先の軌道誤差10mm超過 | ボトル版と同様に警告と測定値を残して続行する |
| 帰還時に開始姿勢から2度以内へ戻ったと確認できない | 途中中断せず解除まで進み、帰還精度未確認として記録する |
| 衝突、関節・指令上限、大きな追従異常 | ボトル版にもある停止条件を維持する |

「腕のずれでは止めない」は通常の軌道精度の判定に適用する。
初回指令の一致、関節・速度・加速度・トルク上限、衝突、継続する大きな追従異常など、
現在のボトル版にもある停止条件は維持する。
腕の誤差を許容する設定によって、脚・腰・骨盤の監視まで緩めない。

## 実装方針

1. 送信方式、下半身・腰の監視、腕の逸脱判定を独立して選べる構造にする。
   現在の `execute_after_plan` はこれらの一部をまとめて切り替えるため、
   ボタン版にそのまま流用して下半身監視まで緩める変更は行わない。
2. ボタン用bashの本押しと接触前診断を同期送信にする。
   検査した各指令を1回ずつ送り、目標の飛ばしや重複送信を避ける。
   ここでの同期は軌道更新と送信を揃える意味であり、各目標への到達待ちを追加するものではない。
3. 腰3軸の開始時の現在角保持、`kp=60`・`kd=1.5`、各軸10Nm以内の重力補償、左腕保持を引き継ぐ。
4. 腕の通常の軌道誤差で確認入力待ちや再計測停止を挟まない。
   最後5mmから5cm退避までの目標固定、固定区間専用の期限なし、自動押し直しなしを維持する。
   起動側の既存の子プロセス100秒上限と通信監視は維持する。
5. 起動時と結果ログに、同期送信、下半身監視は厳格、腕の軌道誤差は記録して続行、という適用方針を明示する。

既存の起動コマンド、上下ボタンの選択、実測ストロークとボタン寸法による事前検査、
新しいRGB-D画像3枚とシミュレーション3条件による開始判定は維持する。

主な確認箇所は、実行設定を組み立てる [robust_push.py](../real/robust_push.py)、
監視と実行を行う [robust_execution.py](../robust_execution.py)、
ボタン版の回帰試験 [test_robust_button.py](../tests/test_robust_button.py)。

## 結果とログ

動作の完走、点灯確認、帰還精度、解除結果を別々に記録する。
腕の誤差が残っても予定経路の実行と解除まで進めるが、
帰還を確認できなかった場合は帰還確認済みと記録しない。
途中停止の有無と、最終結果の確認状態を区別する。

帰還精度未確認の場合も解除後に結果を返し、途中の入力待ちや自動再試行は追加しない。
現行の本押しの成功判定は動作完了・点灯・帰還確認・解除の成立とし、
動作が完走しても確認不足なら終了後の結果は未確認として扱う。

## 検証と再開手順

- 腕の開始姿勢差、手先の軌道誤差、帰還誤差を与え、警告を記録して解除まで進むことを確認する。
- 同時に脚・腰の異常や通信断を与え、腕の緩和設定に影響されず停止することを確認する。
- 検査した指令と実送信が1対1で対応し、腰の保持目標と補助トルクが送られることを確認する。
- 遮蔽対応、固定区間専用の期限がないこと、6配置と各3条件のボタンシミュレーションを再確認する。
- 既存ボトル版の起動引数、監視設定、送信方式、計画と実行の回帰を確認する。
- 以前判明した11件のテスト不整合を現行仕様に合わせて修正し、全体回帰を通す。

11件の内訳と修正対象は以下のとおり。

| 件数 | 不整合 | 修正方針 |
| --- | --- | --- |
| 7件 | 模擬SDKに腰保持の初期化がなく、一部は腰へ指令しないという旧仕様を期待している | 現行の腰と左右腕17軸の保持仕様で初期化・期待値を揃え、トルク拒否と解除の検証が実際に走るようにする |
| 2件 | 時間計測用の代用品が新しい引数と警告リストの戻り値に未対応 | 現行の関数契約へ合わせ、正常時と有効化途中の失敗時の解除時間を確認する |
| 1件 | 通信断後にスレッドが終了するという旧仕様を期待している | 解除、再有効化拒否、解除結果の応答、切断後の終了を確認する |
| 1件 | 保存軌道の移動量が旧モデルの期待値のまま | 現行の腰・左腕保持と腰重力補償を含むモデルで基準値と条件を記録し直す。許容幅を広げるだけの修正はしない |

11件はいずれもボタン版追加前の `26a8f18` でも再現を確認済み。
保存したボトル軌道の3条件は現在も物理的な合格条件を満たすが、旧期待値との差が
約0.24〜0.70mmあるため、旧期待値から±0.1mmという比較で失敗する。
基準値を更新する際も、押し距離・衝突余裕・追従・帰還の合否基準は維持する。

帰宅後はこの文書を実装の基準として作業を再開する。
実機での安定性は、コードと模擬試験の確認後、接触前診断と本押しで別途確認する。
