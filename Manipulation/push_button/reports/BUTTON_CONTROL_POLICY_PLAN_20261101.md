# ボタン版の監視統一・15mm押下・4条件検証

2026-11-03のユーザー合意に合わせ、2026-11-01の保存案を更新した実装仕様。
旧案の「ボタンの100ms監視・脚腰の厳格監視を維持する」という方針は、この仕様で置き換える。
実機への接触試験はソフトウェア検証と分けて扱う。

## 起動と標準設定

既存の `real/run_robust_button.sh check|precontact|push` と
`real/run_robust_button_press.sh --button-direction up|down` を使用する。

| 項目 | 標準値 |
| --- | --- |
| ストローク | 15mm（CLI > 試行JSON > 未指定時の既定値） |
| 探索上限 | 30秒・50候補 |
| 条件 | 基準・奥3mm・左3mm・右3mmの4条件 |
| 採用方式 | 最初に4条件すべて完走・合格した経路で探索を終了し即実行 |

明示的なnullや範囲外のストロークは拒否する。実行回の設定コピーへ反映し、元の設定は上書きしない。
`check` は重み0の入力・計画・出力確認で、腕制御を有効にしない。
古い試行JSONの3条件指定は実行回のコピーで4に更新する。
左右はパネル面内の水平方向（鉛直と押下法線の外積を左とする）。手前3mmは通常検証から外す。
基準・奥には旧版の乱数標本0/2を使い、左右には標本3/4を追加して比較可能性を保つ。
実行前は件数だけでなく4条件の名前・変位・完走・合格も検査し、旧3条件の計画からは開始しない。
ボトル版の3条件、初回RGB-D安定確認と増光確認の画像3枚は従来どおり。

## ロボット監視と送信

ボトル・ボタンの本押しと接触前診断は同じ共通設定を参照する。
状態受信・制御更新400ms、脚速度0.5rad/s、IMU角速度0.3rad/sを上限とする。
ボトル版で警告扱いとなる姿勢偏差、FK追従誤差10mm超過、帰還精度不足は測定値を保存して続行する。
通信断、直立範囲外、衝突、関節・速度・加速度・トルク上限、継続する大きな関節追従異常は停止条件。

検査済み指令を1回ずつ同期送信し、送信完了から次の送信まで20ms以上空ける。
腰の開始時現在角保持、kp=60・kd=1.5、各軸10Nm以内の腰重力補償、左腕保持を引き継ぐ。
ボタンの画像追跡・対象変化の監視はロボットの偏差記録と分離する。
最後5mmから5cm退避までの目標固定、固定区間専用の期限なし、区間外の新しい観測要求を維持する。
子プロセス100秒上限、ブリッジの通信監視、Ctrl+C時の解除を維持する。

## 条件別のシミュレーション判定

15mmストロークのボタンに限り、検証位置変位が押下法線方向+3mmのときだけ下限を11.75mmにする。
条件番号には依存しない。基準・左右3mmは13.50mm、全条件の上限は16.00mm。
別ストロークや別の位置変位は従来どおりストロークの90%を下限とする。
接触力40N、追従誤差10mm、障害物余裕3mm、関節余裕・帰還誤差の基準は維持する。
目標ストローク、補償、検証する経路や物理モデルは判定変更から独立している。

## 完了とログ

本押しは動作完走・解除・増光確認、接触前診断は診断完走・解除で完了とする。
帰還精度未確認だけでは未完了にせず、home_completed=false・誤差・警告を残す。
物理的な押下成功は画像上の増光とは別であり、physical_press_successはnull。

設定・監視方針・位置変位・適用した押下下限/上限・最大押下深さ・不合格理由を保存する。
候補数、物理評価候補数、条件試行数、最初の合格までの時間を区別する。
条件名はnominal・far_3mm・left_3mm・right_3mm。50候補がすべて物理評価に進めば最大200試行。
全候補比較は `robust_planner.search(..., evaluate_all=True)` で行い、最初の合格経路を保持したまま評価を続ける。
通常の実機入口は最初の合格で終了する。

## 検証

- 状態・更新400ms境界、姿勢・FK・帰還偏差、速度超過、通信断、衝突、カメラ異常、遮蔽、解除を模擬試験する。
- 15mm/+3mm以外への緩和の波及と、11.75mm/16.00mmの境界、他の不合格理由を確認する。
- 同期送信が指令と1対1で対応し、腰保持・補助トルクも送られることを確認する。
- 代表配置（高さ980mm・前方360mm）で30秒/50候補を比較する。事前実験の合格候補は0・4・13・21・28・32・36。
- 通常探索で候補0を採用し終了すること、既存ボトル版と1.5mmボタンの回帰を確認する。
- 変更前の全体試験は526合格・40スキップ・11不合格。既知の模擬SDK初期化、監視の代用品、通信断後の応答、保存軌道の旧期待値を現行契約へ合わせて検証する。

現場では `check` → `precontact` → `push` の順で確認し、計画採用・動作完走・帰還精度・解除・増光確認を別々に記録する。
