実機用ボタン押下を realistic で完了させるための分析・実装プラン（2026-10-30）

対象は `real/align_button.py` の「押下 → 5cm退避 → 画像で点灯確認 → 未点灯なら同じストロークで1回だけ再試行 → 行きの関節経路を逆にたどって復帰」。成功は、対象ボタンの点灯、画像による確認、開始姿勢への復帰、腕制御の解除までがそろった場合とする。

前回の5試行は、MenagerieモデルにYadaのrealisticと同じ分布の乱れを加えた専用環境である。元のYada評価環境とは機体・手先・カメラ・配置が異なる。このプランの対象も、まずこの実機用処理を通す環境とする。

**今回確認したこと**

前回と同じseed 0〜4を、制御判断を変更せずに診断ログを追加して再実行した。5試行とも、停止理由・シミュレーション経過時間・制御コードのSHA-256が前回と一致した。いずれも押下前に停止し、点灯確認・押し直し・逆経路復帰には到達していない。

ここでの「件」は検出枠ごとの推定回数。同じフレームに複数枠がある場合を含む。

深度については、`vision.py` が外れ値を除いた後、残った点の「最大残差 > 2mm」を理由に全体を棄却している。今回の棄却では法線角度の15度制限には達していない。最大値に強く依存する条件がノイズで計測を落としていることは確認できた。真の遮蔽を見分ける能力を保った推定方法への変更が必要。

重複検出については、録画アダプターがup/downのクラス情報を捨てて、全枠をボタン候補に変換している。通常の実機側はbuttonクラスの重みを要求しており、今回の2件をそのまま実機側の検出性能と解釈できない。

**押下以降で確認が必要な点**

- `ContinuousNormalController` はストローク1.5mmに対し、完了誤差50µm以内を0.12秒要求する。試行3の位置合わせ中の姿勢で、設定された関節ノイズをヤコビアンで位置へ伝播すると、前後方向の標準偏差は約0.158mm、3軸のRMSは約0.403mm。線形近似であり押下姿勢の実測ではないが、完了条件・過押し判定とノイズの整合性を調べる根拠になる。
- 固定された床座標の目標に対し、現在のFKは骨盤のroll/pitchを反映するが、並進とyaw変化は追わない。画像は撮影時刻より後の姿勢で座標変換される。揺れ・画像遅延・取り付け誤差を個別に切り分ける必要がある。
- 点灯確認でも `_candidates()` を通り、接近時と同じ厳しい深度推定を要求する。このままでは物理的に押せても画像判定不能になり得る。
- 逆再生は関節指令の経路を保証する。体が動く状況で、手先の世界座標の経路まで一致する保証にはならない。実際の接触と復帰を最後まで測る必要がある。

**変更の具体的な制約**

- 5cm退避、点灯の増光30・新しい3フレーム、判定不能時は押し直さない、同じストロークで最大1回だけ押し直す、追加18cm退避を入れずに逆再生、という合意済みの動作を検証の基準にする。
- 1cmの指令差上限は、補正案を制限するためにも使う。実測の大きな追従異常の検査を外さない。試行3の修正は「上限を大きくする」ことを必要としない。
- 重複の統合は画像上の重なりと対象の同一性を確認する。単に25mm以内の全候補をまとめない。信頼度の高いラベルをそのまま押す方向としない。試行2では同じ下ボタンのup誤分類の信頼度がdownより高かった。
- 深度の品質閾値・押下完了条件は、ノイズ分布と物理的な接触結果を測って設定する。前回5seedだけが通る定数選びをしない。許容精度を達成できない場合は、視覚的な相対位置補正や校正の改善を先に行う。
- 位置のフィルターは遅れも評価する。平滑化した値による完了判定と、生の状態・保守的な誤差幅による過押し監視を分ける。物理的なボタンの移動限界を、観測ノイズの大きさに合わせて増やさない。
- 押下開始後に画像で横方向の目標を動かさない。関節経路は押下前に固定し、押下・退避・再試行のサンプルを行きの履歴へ混ぜない。
- シミュレーターの正解座標、真の接触状態、点灯フラグは評価専用とする。制御はRGB-D・関節状態・IMUなど実機で得られる情報を使う。

**評価器を先に整える理由**

前回の録画では、Menagerieの位置制御の基準kp=500へ±10%の乱れを加えている。実機の `ArmSdk.publish()` は腕の主要関節kp=40、手首kp=15、kd=1.5、tau=0であり、追従の条件が異なる。録画用 `Motion` は実機のバックグラウンド送信を置き換えており、追従異常の継続監視と制御解除も完全には再現していない。YOLO推論中に物理時刻が進まない点、仮想カメラが骨盤固定である点も評価条件に明記する。

前回条件は比較用に残し、実機設定を反映した条件を別に評価する。実機の成功を見込む根拠には後者を使う。画像遅延と推論時間、指令遅延、撮影時刻と状態時刻を記録し、保持中も物理シミュレーションと監視を進める。

接触力は手先と対象ボタン、腕と壁・パネル、自己接触を区別して集計する。現在の録画スクリプトの「ボタン以外の最大力」は脚などの接触も含み得るため、腕の安全な復帰の指標にそのまま使わない。

**検証の進め方と完了基準**

1. まず今回の5seedを固定した回帰セットにする。乱れなし、深度のみ、検出重複、遅延のみ、モータのみ、揺れのみ、取り付け誤差のみ、全乱れを同じ配置で比較する。機体・ボタン配置・対象は各比較で固定し、外した乱れ以外の乱数系列が変わらないようにする。
2. 認識の単体検証には、今回の失敗画像と深度、重複枠、2個の実ボタン、手の遮蔽を使う。追従の単体検証には、今回の5.346mmの偏り、応答遅延、進行しない腕を使う。既存の点灯・復帰・共有カメラ・ボトルの回帰も対象にする。
3. 最初の到達点はseed 0〜4すべてで「正しいボタンを押す → 点灯を画像確認 → 5cm退避位置から行きの逆経路 → 開始姿勢へ復帰 → 解除」が完了すること。物理点灯と画像判定は別々に記録し、点灯した瞬間で評価を打ち切らない。
4. 改修前に未調整のseed 5〜24を追加の評価セットとして固定する。20seedそれぞれ上・下を押す40条件で確認し、最初の目標を40/40の完了とする。途中で調整に使った場合は、別の未使用seedで再評価する。完了率、誤ボタン、画像の偽陽性・偽陰性・判定不能、接触、押込量、最大追従差、所要時間を全試行分出す。
5. 通常成功と別に、初回未点灯→再試行成功、2回とも未点灯、画像欠落、画像の明暗混在、戻り経路の干渉、更新停止、解除失敗を故障注入で検証する。成功扱いせずに、それぞれ定めた停止・復帰・結果出力へ到達することを確認する。

合格条件は、対象ボタンのみの物理点灯と画像確認、押込量・速度・追従差の上限順守、壁・パネル・自己への新たな腕の衝突がないこと、開始姿勢から各関節2度以内を連続3回確認すること、解除成功。追加の接触量が見つかった場合は数値と発生段階を報告し、合格条件をその場で緩めない。40/40は開発上の到達目標であり、実機や全条件での成功率の保証ではない。

最終成果物は、実装差分、固定条件の全結果JSON、失敗理由別集計、同じ5seedの新しい5本の動画とする。
