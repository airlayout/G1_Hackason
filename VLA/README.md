# VLA（Vision-Language-Action）

## 要点（誤解されやすいところ）

- **ゼロショットではない。** 使った checkpoint は、このタスク専用に微調整されたもの。「学習なしで動かした」だけで、未知のタスクへの汎化は試していない。
- **成功は安定しない。** 同じ条件で、成功する回と失敗する回がある。3 回では成功率は測れない。
- **公式 checkpoint は再現しにくい。** こちらは 1 回中 0 回。NVIDIA/Isaac-GR00T の issue #574 にも 0/11 の報告がある。

## 置き場所の方針

- 軽いもの（動画 mp4、一覧 JPEG、スクリプト、記録）はこのフォルダに入れる。
- 重いもの（Rerun の `.rrd`、約 68MB）はリポジトリに入れない。`make_rrd.py` で作り直せる。作った 1 本は omen の `~/vla_results/` にある。
  （omen = 実験に使った GPU 付きの Ubuntu PC の、ssh の接続名。詳細は [sim/README.md](sim/README.md)）
- モデルの重みは入れない（`*.pt` は `.gitignore` の方針どおり）。

## 次にやるなら（候補。今は着手しない）

- **先に action / state / 画像を記録する rollout を用意する。** 今の評価スクリプトは動画と成功率しか残さず、失敗の原因を数値で確かめられない。
- 開始状態（seed）を固定して回数を増やし、成功率とばらつきの原因を切り分ける。
- 実機で試す場合は、`sim/` と `real/` を分ける他フォルダの流儀に合わせて `real/` を作る。
