# G1 人検知仕様

## 1. カメラ仕様

| 項目 | 仕様 |
|---|---|
| カメラ | 外付けWebカメラ |
| 取付位置 | G1頭部 |
| 水平画角（FOV） | **約70°** |
| 解像度 | **1080p程度** |
| フレームレート | **30fps程度** |
| 接続 | USB |
| 用途 | 人物検知・視認判定 |

※一般的なWebカメラの65〜78°程度を前提にする。

---

## 2. 人物検知条件

「YOLOが人を検出した」だけでは、**見つかった判定にはしない**。

以下をすべて満たした場合に「見つけた」とする。

```text
人物検出
  ↓
① 視認角度内？
  ↓ YES
② 視認距離内？
  ↓ YES
③ 遮蔽物なし？
  ↓ YES
④ 一定時間以上検出？
  ↓ YES
「見つかった」
```

### 初期パラメータ

| 条件 | 初期値 |
|---|---:|
| 水平視認角 | **±35°（計70°）** |
| 最大視認距離 | **5m** |
| 最小距離 | **2.5m** |
| 遮蔽 | **遮蔽されていれば検知しない** |
| 検知継続時間 | **0.2〜0.5秒程度** |
| 対象 | 人物（Person） |
| カメラ外 | 検知対象外 |

---

## 3. 安全条件との関係

ここはゲームルールと分離する。

```text
          5m
    ┌─────────────┐
    │   👤 ←検知   │
    │             │
    │             │
    │    🤖 G1    │
    │   ┌─────┐   │
    │   │2.5m │   │
    └───┴─────┴───┘
          ↑
       安全停止
```

- **2.5m以内**：ゲーム上の検知とは別に、安全制御
- **2.5〜5m**：ゲーム上の視認判定
- **5m超**：原則としてゲーム上は見えない
- **パーティションの裏**：距離内でも見えない

つまり、

> **「5mまで見える。ただし2.5m以内には近づかせない」**

という設計。

---

## 4. 仕様として一言でまとめるなら

> **G1頭部に水平画角約70°のWebカメラを搭載し、YOLO等で人物を検出。G1正面±35°、距離2.5〜5mの範囲で、遮蔽物がなく一定時間以上人物を検出した場合に「見つかった」と判定する。2.5m以内への接近はゲーム判定とは別に安全停止する。**

## 5. 検知後のG1の反応パターン

「見つかった」判定が出たあと、G1がどう振る舞うかで体験が大きく変わる。
これはゲームルール（ミス確定 or チャンスあり）の設計そのものであり、
比較検討が必要。

| パターン | 検知後のG1 | プレイヤー体験 |
|---|---|---|
| **① 止まらない** | そのまま巡回 | G1が気づいたことが分かりにくい |
| **② 数秒止まる** | その場で2〜3秒停止 → 巡回再開 | 「今、気づいた？」という**不確実な緊張感** |
| **③ 止まる＋人が移動した方向を見る** | 停止 → 最後に人が移動した方向へ向く → 巡回 | **「見つかった！」が明確**。隠れる行動を誘発 |
| **④ 止まる＋人の方向へ行く** | 停止 → 人の方向へ接近 | **最も強い緊張感**。ただし安全・難易度が大きく上がる |

### 方向性

今回のコンセプトが**「見られたら、隠れろ」**なら、まずは **②と③を比較**する
のが面白い。

特に②は、**G1が人を検知したことを明示しすぎない**ので、プレイヤーがG1の
挙動を観察するゲームになる。これは「G1の目を盗む」というコンセプトとも
相性が良い。

④（追跡）は緊張感が最も強い一方、安全面・難易度の設計コストが大きく増える
ため、MVPでは採用しない。
