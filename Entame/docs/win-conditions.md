# 勝利条件の検討

リアル体験型ゲームの「勝利条件」を検討し、G1企画向けに3パターンへ絞り込んだ。

## 設計の基本方針

**目的（何をするか）**と**制約（G1に見つからない）**を分けて考える。

```
目的：宝を持って帰る／ボタンを押す／ゴールする  など
制約：G1に見つからない
```

目的側は極力シンプルにし、「G1に見られている」という制約だけでゲームの
難易度と緊張感を作る。目的側を複雑にする（謎解き等）と、
「G1の目を盗むゲーム」ではなく「謎解きゲーム＋G1」になってしまうため、
今回は謎解き系の目的を採用しない。

## 体験ゲームの基本パターン（一般的な整理）

各パターンの「G1エンタメとの相性」は、単に面白そうかではなく
**「そのゲームをG1でやる必然性があるか」**で評価する。評価軸は以下の3つに絞る。

| 軸 | 見るポイント |
|---|---|
| **G1ならでは** | G1がいることで体験が大きく変わるか（G1がいなくても成立するなら低評価） |
| **ハラハラ感** | 「見つかるかも」という緊張・駆け引きが生まれるか |
| **わかりやすさ** | 来場者が説明を聞かなくても、何をすればいいか理解できるか |

| パターン | 勝利条件 | G1ならでは | ハラハラ感 | わかりやすさ |
|---|---|:---:|:---:|:---:|
| 持ってくる | 時間内に目的物を取得して戻る | ◎ | ◎ | ◎ |
| 生き残る | 時間まで捕まらずに生き残る | ◎ | ◎ | ◎ |
| 謎を解く | 時間内に謎・課題をクリアする | △ | △ | ○ |
| 通り過ぎる | 目的地まで到達する | ○ | ◎ | ◎ |
| 守る | 対象を最後まで守る | ○ | ○ | ○ |
| 追いかける／捕まえる | 対象を捕捉する | ◎ | ◎ | ○ |
| 指定場所に置く | 物を正しい場所へ運搬する | △ | △ | ○ |
| 作動させる | 指定された装置・ボタン等を操作する | △ | ○ | ○ |
| 集める | 複数の対象を集める | △ | ○ | ○ |
| 点数を稼ぐ | 制限時間内に最高スコアを出す | △ | △ | △ |
| 見つける | 隠された対象を発見する | △ | △ | ○ |
| 騙す | 敵に気づかれず、注意をそらして目的を達成する | ◎ | ◎ | △ |

「持ってくる」「生き残る」「通り過ぎる」が3軸とも高評価であり、
下記の3パターン（盗む／逃げ切る／突破する）に対応している。

## 絞り込んだ3パターン

### ① 盗む

**「時間内に宝を持って帰れ」**

`START → G1を避ける → 宝を盗む → G1から逃げる → START`

- 一番エンタメ性が高く、「盗む」という目的が直感的
- 現行企画（「G1の目を、盗め。」）をそのまま発展できる

### ② 逃げ切る

**「時間までG1に捕まるな」**

- 目的物なし、純粋なステルスゲーム
- ルールが最も単純で、PoCしやすい
- G1の「見る・追う・反応する」という挙動そのものを体験させられる

### ③ 突破する

**「G1に見つからずゴールせよ」**

- 「宝を盗んだこと」の検知が不要（ゴール到達の検知だけで成立）
- 技術的に実装しやすい
- 「G1の監視を突破する」というコンセプトが明確

### ④ 救出する（2026-11-07 追加。2D ゲームに実装済み、実機は未検証）

**「監視員の目を掻い潜って、囚われの仲間を救出せよ」**

`START → G1・Pepper を避ける → 囚われのミニロボット（LOVOT）のもとへ → 救出 → 一緒に START へ帰る`

- ①盗むの「宝」を「ミニロボット」に置き換えたもの。目的が明確で、ストーリーにしやすい。
- ミニロボットは TARGET の位置で**ステイモード**（動かない）。プレイヤーがそばまで行き、LOVOT の頭部にあるセンサーホーンの**モードスイッチ**で通常モードに切り替えると、人に付いてくる。人とミニロボットの両方が START に戻れば CLEAR。
- ミニロボットは遅い（0.3 m/s）ので、人は待ちながら戻る。ここが緊張の山場になる。
- 2D ゲームの操作: ミニロボットの 0.6 m 以内で Space キー（実機のモードスイッチの代わり）。
- ステージの JSON は変えない。「LOVOT を救出する」オプション（「LOVOT と一緒に行く」とは別）をレベル選択（エディタのテストプレイでも）で選ぶ。TARGET の位置がミニロボットの置き場所になる。
- **仮置き・未確認**:
  - ステイモード中のミニロボットは、G1・Pepper に見つかっても判定しない（人を見る検知と、囚われの仲間の扱いを分けた仮置き）。
  - **実機では、LOVOT が通常モードに切り替わったことをゲームの判定に伝えられない**（2026-11-07 ユーザー回答）。運営の「救出」ボタンも作らない。実機では、プレイヤーがスマホで申告する既存の流れ（「TARGET を取った」→「START に戻った」）に載せる。つまり実機では救出の成否も、LOVOT が一緒に戻ったかも、システムは判定しない。LOVOT を連れて戻ったかは、**プレイヤーが goal（「START に戻った」）をタップして確定する**（2026-11-07 ユーザー回答）。2D ゲームの Space キーは実機の代わりに操作を再現するだけ。
  - ダッシュボードのマップには、TARGET の初期位置だけを出す。LOVOT の位置は出さない（2026-11-07 ユーザー回答）。
  - ステイモードの LOVOT が実際に動かないか、スイッチの位置と押しやすさ。LOVOT の実機での確認が要る。
  - 救出の操作に要する時間は 0 秒（押した瞬間）。実機で押して復帰するまでの時間は未測定。

## 除外したパターン

- **謎を解く**：ゲームの主眼が「G1に見られない」から逸れるため不採用
- **守る**：「参加者がG1に挑む」という今回の構図と合わないため不採用

## ワンフレーズ案

> 「盗む」「逃げ切る」「突破する」——G1の監視をかいくぐり、目的を達成せよ。
