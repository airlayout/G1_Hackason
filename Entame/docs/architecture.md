# Architecture — 潜入ゲームをどう実現するのか

## データの流れ

```
Camera
  ↓  BGR画像
Person Detection
  ↓  bbox
Depth
  ↓  距離(m)
Visibility
  ↓  見えている / 隠れている
Game State
  ↓  WAITING / PLAYING / DETECTED / ESCAPING / SUCCESS / TIMEOUT
G1 Reaction
```

## 層の対応（依存は上から下への一方向のみ）

```
perception   カメラ → 人物検知 → 距離 → 視認判定（★企画の中核）
tracking     フレーム間で同一人物を追う（未実装）
game         このゲーム固有のロジック（状態機械・ルール・イベント）
robot        G1を反応させる（旋回・頭部・音）
```

下の層は上の層を知らない（`perception` は `game` を import しない）ため、
他用途（館内案内・巡回）へそのまま持ち出せる。

## 実行時の構成

```
┌─ 操作PC ─────────────────────────┐
│  perception → game → robot       │
└──────────┬────────────────────────┘
           │ 有線 / ZMQ（映像）
           │      DDS（制御・未実装）
┌──────────▼────────────────────────┐
│  G1                                │
│  映像配信サーバ                     │
└────────────────────────────────────┘
```

処理は全て操作PC側で行う。G1側には映像配信サーバだけを置く。

## 他チームとの境界（重要）

**SLAM / Navigation / Localization はこのフォルダで扱わない。** `Common/` の担当。

```
        Common（地図作成・自己位置推定・巡回・安全停止）
                │
                │ 提供されるもの:
                │   - G1の位置・姿勢
                │   - G1の稼働状態（正常 / 異常）
                ▼
┌───────────────────────────────────────┐
│  Entame（潜入ゲーム）                  │
│                                       │
│   Person Detection                    │
│   Visibility                          │
│   Game Logic                          │
│   G1 Reaction（旋回）                  │
└───────────────────────────────────────┘
                │
                │ こちらから出すもの:
                │   - 停止要求（安全）
                ▼
        Common
```

現時点のPoCは**G1が定位置で旋回するだけ**なので、位置情報が無くても成立する。
位置情報が必要になるのはNavigation連携以降。

## 設定の分離

しきい値・時間・速度はコードに書かず設定ファイルに分離する方針:

| 設定内容 |
|---|
| カメラ、検知しきい値、視認FOV、焦点距離 |
| 制限時間、検知ペナルティ、警戒レベル |
| 接続先、旋回上限、安全距離 |

「視認距離を5m→4mにしたい」でコードを触らなくて済むようにするため。

## 判定の二系統（混ぜてはいけない）

| | ゲーム判定 | 安全停止 |
|---|---|---|
| 入力 | カメラ（YOLO） | 幾何（距離・柵・非常停止） |
| 性質 | 確率的 | 決定論的 |
| 外れたら | ゲームが少し不公平になるだけ | **人が危ない** |
| 実装 | 視認判定モジュール | `safety.md` を参照。別系統で作る |
