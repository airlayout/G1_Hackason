# ステージ・障害物設計案

## 1. 基本方針

**「専用のステージを作る」のではなく、会場にある空間をゲームフィールドとして利用する。**

重視する条件は以下。

- **場所を選ばない**
- **設営・変更が簡単**
- **低コスト**
- **既存設備を活用**
- **観客とプレイヤーを区別しやすい**
- **G1のカメラによる人検知で誤作動しにくい**

---

## 2. ステージは3層で構成

### ① 外周：ゲームエリアの境界

**ロープ／ベルトパーテーション＋床面マーキング**

役割：

- ゲームエリアと観客エリアを区別
- プレイヤーの立入範囲を明確化
- 観客からゲームを見える状態にする
- 会場サイズに応じて自由に変更

**外周を高いパーティションで囲わない。**

→ 観客から見えにくくなる
→ G1のカメラ視野も狭くなる
→ パーティションの必要枚数が増える

---

### ② 内部：G1から隠れるための障害物

**既存のパーティション・壁・柱・家具などを活用**

基本的には、

> **「その会場にあるものを障害物として使う」**

という考え方。

足りない場合だけ、安価な簡易パネル等を追加する。

障害物は、

**高さ150cm程度の不透明なもの**

を基準にする。

ただし、最終的な高さはG1の実機カメラで検証する。

---

### ③ AI：ゲームエリアをROIとして定義

物理的な境界だけに頼らず、G1のカメラ映像上にも、

**GAME AREA**

を設定する。

```text
┌────────────────────┐
│      観客           │
│                    │
│  ┌──────────────┐  │
│  │              │  │
│  │  GAME AREA   │  │
│  │              │  │
│  │       G1     │  │
│  │              │  │
│  │          TARGET│ │
│  └──────────────┘  │
│                    │
│      観客           │
└────────────────────┘
```

人検知した際に、

- ROI外 → **ゲーム対象外**
- ROI内 → **プレイヤー候補**

とする。

これにより、周囲の観客による誤検知を抑える。

---

## 3. 部材構成

| 部材 | 役割 | 基本方針 |
|---|---|---|
| **既存パーティション** | 視界遮蔽 | 会場のものを活用 |
| **簡易パネル** | 視界遮蔽の追加 | 必要な場合のみ購入 |
| **ロープ／ベルト** | エリア境界 | 持ち込み最小限 |
| **床テープ** | START・境界表示 | 安価・変更容易 |
| **G1** | 警備員 | 1台 |
| **ターゲット** | 取得対象 | 1個 |

---

## 4. 段ボール箱は基本採用しない

段ボール箱は安価ですが、

- 高さが一定しない
- 配置が変わりやすい
- カメラ検知の再現性が低い
- 倒れる・動く可能性がある
- 「隠れる場所」としての品質が安定しない

ため、**MVPの標準障害物にはしない**。

ただし、将来的に「倉庫」「潜入」などの演出をしたい場合には利用可能。

---

## 5. ステージ設計

重要なのは、**同じ部材で複数ステージを作れること**。

例えば、

### LEVEL 1

```text
START        G1


       ███

                  TARGET
```

広く、遮蔽物少なめ。

### LEVEL 2

```text
START     ███

               G1

       ███

                    TARGET
```

遮蔽物を増やす。

### LEVEL 3

```text
START   ███
          ███

       G1

             ███
             ███

                    TARGET
```

ルート選択が必要になる。

つまり、

> **パーティションの枚数・配置を変えるだけでステージを変更できる。**

---

## 6. 難易度は「空間 × G1」で調整

1台のG1でも、

| パラメータ | EASY | HARD |
|---|---|---|
| G1台数 | 1 | 1〜2 |
| G1速度 | 遅い | 速い |
| 視野角 | 狭い | 広い |
| 視認距離 | 短い | 長い |
| 障害物 | 少ない | 多い |
| 通路 | 広い | 狭い |
| 巡回ルート | 単純 | 複雑 |
| 制限時間 | 長い | 短い |

と変更できる。

**最初からG1を2台にする必要はない。**

まずは、

> **「G1 1台＋ステージ設計だけで、十分難しいゲームになるか」**

を検証する。

---

## 7. 最終的なコンセプト

今回のステージ設計は、

> ### 「持ち込んだ設備でステージを作る」のではなく、「その場所をステージにする」

という方向が良い。

```text
会場
 ↓
既存の壁・パーティション・柱
 ↓
ゲーム空間を構成
 ↓
ロープで外周を定義
 ↓
AI側でGAME AREAを定義
 ↓
G1がプレイヤーを検知
```

これなら、

**オフィスでも、展示会場でも、商業施設でも、イベントスペースでも展開できる。**

そして、今回のPhysical AIのデモとしても、

> **「ロボットを置く専用施設」ではなく、「既存の空間をロボットが理解してゲームフィールドにする」**

という発展性を持たせられる。
