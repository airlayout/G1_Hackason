# プレイヤーの腕と手でSO-101を操作する設計

対象は標準グリッパーのSO-101フォロワーと、操作用の固定RGBカメラ1台。プレイヤーが腕を前に伸ばした分だけ爪が前へ出て、手を戻すと爪も戻る。上下・左右も同時に操作でき、指をつまむと爪が閉じる。カメラの被写体はプレイヤー。SO-101はUSB経由で関節位置を返す。

## 操作の流れ

1. 操作側の手を選び、カメラをその側の斜め前に置く。初期の目安は正面から30〜45度。両肩・腰・操作側の肘・指先と、伸ばした手が画角に収まる位置に置く。プレビューには同じフレームの肩―肘―手首と手指21点を重ねる。鏡表示は映像と線を一緒に反転し、制御入力は元画像から取る。
2. 模擬モードで、肘を軽く曲げた中立姿勢から「前→戻す・右→戻す・上→戻す」を試す。画面にロボット座標の目標変位をmmで出し、軸・符号と静止時の揺れを確認する。前に伸ばした動きが横や縦に大きく漏れる画角では、カメラをずらしてやり直す。
3. 実機の作業範囲、机面、爪の開閉端を登録する。開始毎に、安定して見えているプレイヤーの手首と、現在の実測関節角から求めた爪先の位置を同時に基準として採る。開始操作だけでは腕も爪も動かさない。指の入力は現在の爪の開きと合ってから有効にする。
4. 「追従開始」中は腕で位置を、指で開閉を操作する。停止後は手を好きな位置に戻し、そこを新しい中立姿勢として再開できる。撮影用に別カメラを使う場合も、操作はプレイヤー側のカメラだけで成立する。

## 人の動きから爪先目標への変換

同一フレームにPose Landmarkerと既存のHand Landmarkerを適用する。肩・肘・手首の3D座標はPoseのworldLandmarks、ピンチ幅はHandの親指先と人差し指先の距離を手のひら幅で割った値を用いる。PoseとHandの3D原点は異なる。操作側の手の対応付けには画像上の手首位置を用い、反対の手との区別がつかないフレームを棄却する。描画には各モデルの画像座標を使う。

左右の肩を結ぶ方向を「右」、腰中央から肩中央に向かうベクトルから右方向の成分を除いて「上」とする。直交する「前」の符号は初回の前伸ばしで確認する。安定した中立区間からこれら3軸を求め、追従中は固定する。胴体が大きく回転した場合は再基準化する。各フレームの操作側の肩から手首までのベクトルをこの基底に投影し、前・右・上の順の値を u とする。

    爪先目標 = 開始時の爪先実測位置 + B × diag(ゲイン前, ゲイン右, ゲイン上) × (u − u開始)

Bの各列は作業台で定義した「奥・右・上」の単位ベクトルをロボット台座座標で表したもの。前は台座から景品のある奥へ向かう方向とし、URDFの軸符号は実機の設置向きと照合する。ゲインの初期案は全軸0.5。人の前方変位200 mmを爪先の前進100 mmに対応させる。これは制御倍率の仕様で、単眼推定の精度保証ではない。目標は毎回開始位置から計算し、腕を伸ばしたまま止めたときに指令が積み上がることを防ぐ。

前処理では肩・肘・手首の可視性、腕長の急変、時刻の連続性、手の対応を確認する。妥当なフレームだけを時刻に応じて平滑化し、静止時の揺れには中立計測に基づく不感帯を適用する。前後の合否は動作中の別テイクで判定する。単眼で前後が安定しない場合は、まず斜め横へ移して再計測し、それでも基準に届かない場合の次案を深度カメラとする。

## Python側の逆運動学と実機指令

- SO-101用URDFの版とハッシュを固定し、実機の標準爪に対応することを確認する。作業点は基準開度における左右の爪先間の中央とし、手先フレームからの固定オフセットを測る。開閉は別の1軸とし、腕のIKには台座から手首ロールまでの5軸を名前順に渡す。
- LeRobot 0.6.1の `RobotKinematics` をFK・IKに利用する案。対応する `placo` のインポートとURDFロードを対象PCで確認する。入力・返却の関節角は度、URDF上の長さはm。既存モードの `use_degrees=False` は正規化値を返すため、新モードの実機アダプターを `use_degrees=True` で生成する。各軸のゼロ点・回転符号・URDFとの差を静止姿勢と小さなジョグで照合する。グリッパーには校正した0〜100の開度を使用する。既存の正規化値向けの速度上限・姿勢登録を角度として流用しない。
- 各周期で実測角を初期解とし、爪先のXYZを優先して解く。初期版ではプレイヤーの手首回転は操作に割り当てない。開始時の把持姿勢を弱い姿勢目標とし、爪が許容傾斜を超える解は棄却する。関節リミット、机面からの余裕、リンクと台座の干渉、関節の飛び、FKで戻した位置残差を確認する。開始時に作業範囲を机上の小領域に設定する。
- 到達可能な目標まで手先速度を時間刻みで制限して一歩ずつ解き、関節速度上限も確認する。範囲外・IK失敗・不連続な解は送らず、実測姿勢を保持して理由を表示する。指令を再送する場合も追跡時刻の鮮度を再確認する。通信故障時は停止状態とし、姿勢保持の成功は実測できた場合だけ扱う。

## 既存コードへの組み込み

| 箇所 | 実装する内容 |
|---|---|
| prepare.py / requirements.txt | Poseモデル、対応URDFと必要資産を版・ハッシュ付きで用意する。既存のHandモデルとブラウザランタイムを共用し、対象PCで確認したIK依存を記録する。 |
| desk.html / app.js | 腕・指の骨格、追跡状態、前・右・上の目標変位、停止理由を表示。中立登録、入力手選択、開閉登録を用意する。推論は最新フレームを優先し、処理待ちの画像を蓄積しない。 |
| server.py | 起動時に既存の2姿勢補間と新しい3D追従を切り替える。新モードでは前・右・上の変位[m]、開き[0〜1]、追従トークン、フレーム連番・時刻を受ける。サーバーで変換・作業範囲・IK・USB指令を管理する。 |
| 模擬バックエンド | 実機と同じFK・IK・制限を通し、目標と模擬爪先を比較できるようにする。現行MockArmの正規化値と新モードの角度は分ける。 |

追従停止・タブ非表示・カメラ切替・必要な腕や手の追跡喪失で新規動作指令を止める。遅延フレームや再接続前の指令を採用しない。フレームの鮮度は同じ時計で評価し、ブラウザの描画時刻とPythonの単調時計を直接比較しない。サーバー側では従来の受信途絶監視（0.65秒）も維持する。復帰は明示操作で新しい中立を採る。

## 合格条件

下記は撮影用の初期目標値。実測結果は未取得。模擬入力、録画した人の動作、実機の順で通す。

| 試験 | 判定 |
|---|---|
| 座標変換の自動試験 | 人が前に200 mm動いた入力で前方目標が100 mm増え、静止して繰り返し処理しても増分ゼロ。右・上・斜め・反転表示も符号を検査する。 |
| 前に伸ばす／引く | 作業範囲の内側で、人が定規の印に沿って200 mm伸ばして戻す。5往復すべてで爪先が奥へ80〜120 mm動き、左右・上下の漏れと戻り誤差が各20 mm以内。作業台の目盛り・横からの記録で実物を測る。 |
| 独立操作 | 腕を静止して指を5回開閉し、腕の目標が10 mm以内に収まる。指を開いたまま前進・下降・上昇しても意図せず爪が閉じない。 |
| 開始・停止と境界 | 開始・再開時の目標は現在位置。手が隠れた後の古い指令、届かない目標、机面に干渉する解を拒否する。腕を戻しただけでは自動再開しない。 |
| デモ通し | 操作用カメラにはプレイヤーだけを映し、前に伸ばす→景品の高さへ下げる→つまむ→持ち上げる→手前へ戻す、を完了する。 |

参考資料は [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)、[Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)、[LeRobotのSO-101用IK設定例](https://huggingface.co/datasets/lerobot/config_examples/blob/a7d512231ddb1acdccb6a31a101a13727e6dbe68/rl/train_config.json)。
