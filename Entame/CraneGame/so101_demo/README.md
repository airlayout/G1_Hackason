# SO-101でお菓子をつかむ動画を撮る

**撮るのは10〜15秒の１カット。** 素手を下げると爪がお菓子に近づく。親指と人差し指でつまむと爪が閉じ、手を上げると袋が浮く。操作者の手と爪と袋を一緒に映す。余裕があれば、再び下げて指を開き、袋を置く所まで撮る。

## このMacですぐ始める

このプロジェクト内に Python 3.12 の実機用環境、LeRobot 0.6.1、Feetech SDK、認識モデルとブラウザ用ランタイムを準備済み。模擬モードはUSBをつながずに起動できる。ターミナルで実行する。

~~~sh
cd Entame/CraneGame/so101_demo   # リポジトリのルートから。すでにこのフォルダにいれば不要
source .venv/bin/activate
python server.py
~~~

Chrome で [撮影卓を開く](http://127.0.0.1:8765)。**最初は画面上部が「模擬モード」**。カメラ一覧を更新し、操作用カメラを選び「映像を開く」。手が映れば認識状態と指先の点が出る。映像や推論はこのPC内で処理する。操作するタブは１つにする。

### 次回そのまま貼る起動コマンド

準備済みのPCで、このフォルダに移動してから貼る。GUIのURLは **http://127.0.0.1:8765**。止めるときは Ctrl+C。

~~~sh
cd Entame/CraneGame/so101_demo   # リポジトリのルートから。すでにこのフォルダにいれば不要
source .venv/bin/activate
python -m unittest -v test_server   # 自動テスト（１７件）。省略可
python server.py                    # 模擬モード。実機は下の「実機に切り替える」
~~~

実機を使うときは `python server.py` の代わりに、実際のポート名とIDで次を実行する（Macのポートは `/dev/cu.usbmodem…`）。

~~~sh
python server.py --port <ポート名> --robot-id <校正に使ったID>
~~~

## 持ち物と配置

| 用意するもの | 使い方 |
|---|---|
| SO-101フォロワー、対応電源、USBデータケーブル、固定用クランプ | テーブルに台座を固定。リーダーは使わずに撮影できる。12V仕様のフォロワーにはキット指定の電源を使用。公式部品表では12V仕様に12V・5A以上を案内しており、標準のリーダーは電圧仕様が異なる。各機の表示を優先する。 |
| Webカメラ１台 | 手の読み取りと録画を、この1台で行う。手を正面から、親指と人差し指が重ならない向きで映し、手・爪・お菓子が一緒に映る位置に置く。手はアームの可動域の外で動かす。 |
| 軽い個包装菓子を数個 | 例は小袋のおかき、マシュマロ。袋の中身に少し厚みがあり、爪が両側に入るものを選ぶ。包装の加工は不要。平置きで爪が机に当たるときは、袋の中央の下に小さな台を置いて両脇を浮かせる。 |

## 実機に切り替える

1. 模擬サーバーをターミナルで Ctrl+C。フォロワーを安定した休止姿勢で支持し、電源とUSBを接続。爪の間に指を入れず、電源を切れる位置で操作する。
2. 同じ仮想環境で下記を実行。ポート名と以前校正に使用したIDを確認する。Macの例は `/dev/cu.usbmodem…`、Ubuntuは `/dev/ttyACM0`、Windowsは `COM3`。実際に表示されたフォロワーの値を使う。

~~~sh
python -m serial.tools.list_ports -v
~~~

3. **校正済みの場合**はファイル名から拡張子を除いたIDを使う。別PCや旧環境から引き継ぐ場合は、この実機の校正JSONが入ったディレクトリを `--calibration-dir` で指定できる。校正ファイルがない場合は公式CLIを実行し、画面の指示に従う。下記はポート名とIDの例。組立済み・設定済みのモーターのIDを書き直す必要はない。新品で各モーターが未設定なら公式組立手順の「Configure the motors」から始める。

~~~sh
lerobot-calibrate --robot.type=so101_follower --robot.port=/dev/ttyACM0 --robot.id=candy
~~~

4. 実機モードを起動し、撮影卓を再読み込み。「実機接続」の表示を確認。指定した校正ファイルの有無と、実機の校正との一致を起動時に検査する。接続・終了時はトルクの切り替えがあるので、腕を休ませる位置を用意する。

~~~sh
python server.py --port /dev/ttyACM0 --robot-id candy
~~~

[LeRobot公式のポート確認・組立・校正手順](https://huggingface.co/docs/lerobot/so101)

## ４点の登録から撮影まで

画面の最上部の「**次にやること**」に、次の手順と進み具合（✓）が出る。位置の登録欄には、**登録した瞬間の各関節の実測値の表と登録履歴**が出る。登録点どうしが食い違う場合（上下２点が近すぎる・離れすぎ）は、数値つきの説明が登録の直後に赤字で出る。

| 順番 | GUIの操作と目で確認すること |
|---|---|
| 1. つかむ位置 | 台座・肩・肘・手首の「＋」「−」を１回ずつ押し、爪が袋の左右に来る姿勢を作る。爪先と台の間に余裕を残し「つかむ位置を登録」。袋の位置を爪に合わせると早い。 |
| 2. 開閉 | 位置の登録は不要。画面の「指を最大に開く」「指をくっつける」を1回だけ押して測る（押して3秒後から1秒間の角度の中央値。結果はサーバーの `finger_calibration.json` に保存し、ブラウザを替えても再度の校正は不要。校正前は「追従開始」不可）。親指の先と人差し指の先の距離を手のひらの長さ（手首〜中指の付け根）で割った比が、最大に開いた比で最大開、くっつけた比で最大閉。両端の 5% は 0・100% に寄せる。比と角度は画面の「手を認識」の行に出る（角度で測る方式は、つまんでも角度が大きく残り「閉じても開き」と誤判定したため 2026-11-22 に比へ変更）。グリッパー側の範囲は `server.py` の `GRIPPER_CLOSED`・`GRIPPER_OPEN`（向きは実機で未確認）。 |
| 3. 持ち上げた位置 | 袋が数cm浮くように、肩または肘を少しずつ動かし「持ち上げた位置を登録」。間の動きが机に干渉しない範囲を選ぶ。袋を元の位置に戻し、撮影前に爪を開く。登録は同じサーバーを終了するまで保持。各ボタンで登録し直せる。 |
| 4. 空運転 | 一度袋を外す。操作用カメラを開き、手首を下のガイド線に合わせ、指を開いて「追従開始」。手を上げ下げし、つまむ・開くを試す。「追従停止」またはスペースキーで止める。手が消えた後は再度ボタンを押して再開する。 |
| 5. 本番 | 停止中に袋をセット。カメラに手・爪・袋が一緒に映るのを確認し「録画開始」。手と爪が同時に動くのが見える速さで、開く → 下げる → つまむ → 持ち上げて一拍待つ。追従停止、録画終了、「動画を保存」。再生して袋が机から離れたことを確認する。 |
| 6. 終了 | 保存済みを確認する。ジョグで腕を低い休止姿勢に戻し、支持できる状態でサーバーを Ctrl+C。 |

保存先はブラウザのダウンロード先。音声なしのWebMまたはMP4。発表ソフトでWebMが扱えず、FFmpegが使える場合は変換できる。

~~~sh
ffmpeg -i take.webm -c:v libx264 -pix_fmt yuv420p -movflags +faststart take.mp4
~~~

## モーター別の制限（詳細設定）

画面右の「詳細設定」（初期は非表示。「詳細設定を表示」で開く。開閉は記憶される）で、関節ごとに次の4つをスライダーで決める。値はすべて可動範囲に対する%。

| 項目 | 意味 | 既定（グリッパー／腕） |
|---|---|---|
| 追従の最大速度 | 手に追従するときの最大速度（%/秒） | 45／11 |
| 1回の最大移動量 | 1回の指令で動かせる量（LeRobot の `max_relative_target`）。速度の天井は「この量 ÷ 指令間隔 65 ms」 | 3.0／1.5 |
| 動かせる下限・上限 | 範囲の外へは、追従でもスライダーでも動かさない | 0〜100 |

- 「保存して適用」で実機に反映し、`limits.json`（git 管理外）に保存する。起動時に自動で読む。ファイルが無い・壊れているときは既定値（壊れていれば理由をログに出す）。「既定値に戻す」で初期化する。
- 追従中は変更できない（サーバーも拒否する）。範囲を今の姿勢より内側に狭めて保存すると、次の指令で腕が範囲の中へ動く。
- 速度を上げるには、最大速度と1回の最大移動量の両方を上げる（画面に「追従の実際の上限」が出る）。

## 追従のデバッグログ

追従を始めるたびに `debug/follow-日時.jsonl`（git 管理外。新しい20件だけ残す）を作る。1行が1つの出来事で、追従がおかしいときに Claude に読ませる。

| ev | 内容 |
|---|---|
| `start` | モード、開始時の姿勢、制限、登録点 |
| `sample` | 手の入力 `inp`（0〜1／-1〜1）、画面側の生の値 `dbg`（距離比・傾き・縮み・手の位置）、現在位置 `cur`、制限前の目標 `want`、実際に書いた指令 `goal`、経過時間 `dt` |
| `error` | 追従中に拒否された指令や通信異常 |
| `stop` | 停止の理由（停止ボタン、手を見失った、入力途絶、モーター切替など） |

次の `sample` の `cur` を前の `goal` と比べると、実機が指令に追えているか分かる。ログを書けなくても追従は止めない。

## 数時間の使い方

組立・校正済みなら、最初の30分をUSB接続・カメラ・爪の確認に、次の45分を袋の位置と４点の調整に、残り30〜45分を練習・撮り直し・動画確認に充てる想定。所要時間は見積もり。袋が滑るときはつかむ力を増やす前に、厚みのある別の袋に替える。カメラは1台で、読み取りと録画を兼ねる。単眼での自由な３次元操作やカゴへの横移動は、今回の撮影範囲に含まない。

## 別PCで準備する場合

**フォロワーが既に動いたPCがあれば、そのPCを優先。** 新しいPCならデスクトップ版Chrome、Python 3.12、USB・Webカメラへのアクセスと、初回のインターネット接続を用意する。以下はこのフォルダに移動して実行。モデル一式は約26 MiBで、取得後はオフラインで利用できる。仮想環境とダウンロード済みモデルはGit管理外。

~~~sh
# Ubuntu / Mac
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python prepare.py
python server.py
~~~

~~~powershell
# Windows PowerShell。環境の有効化は不要
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare.py
.\.venv\Scripts\python.exe server.py
~~~

Windowsでの実機起動は末尾を `server.py --port COM3 --robot-id candy` に替える。校正CLIは同じ `.venv\Scripts` 内にある。USBアクセスが拒否されたときは、別のテレオペプロセスがポートを使用していないか、Ubuntuではユーザーがシリアルデバイスにアクセスできるかを確認する。MacではChromeへのカメラ許可も確認する。

## 要件と設計

- **入力**　MediaPipe Hand Landmarkerで片手を検出。手首の画面上の高さを２点間の位置に、親指先と人差し指先の距離をグリッパー幅に対応させる。距離は手のひらの見かけの幅で割る。手の大きさ・距離が違う人への調整性能は未検証。
- **アーム制御**　手の高さに応じて登録した２姿勢を関節ごとに補間する。経路は関節空間の補間で、先端が厳密に鉛直移動する保証はない。指の開閉と腕の上下は独立して連続操作できる。左右・奥行きは追跡しない。
- **GUI・録画**　localhostのChromeで、モーター校正の確認、カメラ選択、認識表示、現在位置のスライダー（可動範囲に対する0〜100%）、位置登録、開始・停止、録画・保存を行う。追従は明示的に開始する。録画はカメラ映像そのままで、認識点や操作画面は入らない。
- **通信**　ブラウザから同じPCのPythonサーバーへ高さと開き幅を送信し、LeRobotがUSB経由で６軸を制御する。移動量を時間と現在値で制限する。姿勢は正規化単位で扱う。登録区間から離れた姿勢での開始は拒否する。手の消失・タブ非表示・約0.65秒の指令途絶では追従を解除する。ソフトウェア停止はトルクを保持する動作で、物理的な電源遮断とは異なる。
- **モーターの切り替え**　画面の「モーター」欄で、サーバーを止めずに切り替える。**OFF**＝トルクを切り、手で動かせる（自重で下がるので支える）。**やわらか**＝外力で動かせて、外力が無ければ姿勢を保つ狙いのモード（トルク上限 200・D=0 にし、動いた関節の目標を今の位置へ追従させる）。**実機では手で押しても動かず、未解決（2026-11-22 に中断。DEMO_CHECKLIST.md の保留を参照）。** **ON**＝通常の保持。切り替え前に、目標を今の姿勢へ揃えてからトルクを入れるので、腕は飛ばない。OFF・やわらかのあいだは画面の姿勢が手の動きに追従し、「位置の登録」は使える。スライダー・追従開始は ON のときだけ。切り替えると追従は止まる。
- **スライダー移動**　サーバーが「指令位置」を一定の速さ（1回 1 単位）で目標へ進め、実際の位置との差は 3 単位まで。以前の「毎回 実際の位置＋1〜3」方式は、動くたびに差が消えて止まる→動くを繰り返し、肩が揺れ（P=48 では机まで揺れた）、肘は P=16 で 25 単位の指令に 0.09 しか動かなかった（2026-11-22 実測）。新方式は P=16（既定）のまま、肘も肩も届き、ぎくしゃく度（位置の2階差分の標準偏差）は肩 P=48 の旧方式 0.75 → 新方式 P=16 で 0.14。肩の P の引き上げはやめた。
- **実装の入口**　[GUI](desk.html)、[カメラ・録画・手入力](app.js)、[フォロワー制御・模擬バックエンド](server.py)、[モデルの準備](prepare.py)、[自動テスト](test_server.py)。

## モーターの校正と今回の範囲

- 画面の関節値（0〜100%）は、**校正で測った各関節の可動範囲に対する割合**。校正をしないと、同じ%でも腕の姿勢が実機ごとにずれる。
- 模擬モードは校正を省略する（画面は「模擬モードのため不要」）。実機で未校正または実機と食い違う場合は、画面右に公式の校正コマンドを出し、校正が済むまで操作を受け付けない。別のターミナルで校正し、終わったら「校正を確認」を押す。
- **今回できる操作は、手の上下（持ち上げ・下ろし）と指の開閉だけ**。奥行き（前後）と左右（台座の回転）、腕の角度で測る方式は未実装。構想は逆運動学で手首の3次元位置を腕に対応させる方式で、SO-101 の関節の長さと限界角は公式URDFで確認済み（上腕約116mm、前腕約135mm、台座±110°、肩±100°、肘±96.8°、手首の曲げ±95°）。実機・実写での確認はこれから。

## 比較した公開実装

- 作者のExperiment 5にはWebカメラの手で実機SO-101を動かし、箱を器に移す動画がある。公開構成はMediaPipe・MuJoCo・逆運動学を使い、実機対応ブランチはUbuntu 24.04／ROS 2 Jazzyを想定。今回の構成では登録した２姿勢の間だけを動かす。[実機動画と構成](https://convolutedladybug.com/experiments)

- ブラウザ側はGoogle公開のHand Landmarker、実機側はHugging Face公開のSO-101フォロワーAPIを使用する。[Googleの手検出資料](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js) ／ [LeRobotの配布版](https://pypi.org/project/lerobot/0.6.1/)
