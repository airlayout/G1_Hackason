G1 統合デモ 全体像

G1 が決まったコースを歩き、途中で人・バナナ・ぬいぐるみを見つけると、立ち止まって声と腕の動きで反応し、また歩き出すデモです。

1 どんなデモ？ what

G1（ユニツリー社の人型ロボット）が、決まった距離を往復します。歩いている間、カメラの映像から次の 3 つを探しています。見つけたら歩きを止め、反応が終わると歩きを再開します。

🧍

人

「見つけた」反応。検出するとすぐに声が出ます。

腕の動き：見つけた（found）
🍌

バナナ

「驚き」反応。完全に止まってから声が出ます。

腕の動き：驚き（surprise）
🧸

ぬいぐるみ

「驚き」反応。2 回続けて見えたときだけ確定します。

腕の動き：驚き（surprise）

2 登場するもの who

登場するのは 3 つの場所です。操作PCが考え、Jetson が G1 に伝え、G1 本体が実際に動きます。操作PC と Jetson は SSH と UDP でつながっています。

3 1 回の流れ flow

反応は毎回この 5 つの順番で進みます。歩きを止めてから腕を動かすので、歩きながら腕を振ることはありません。

  1. 🚶1 歩く

    決まったコースを一定の速さで進みます。距離と向きを測りながら歩きます。

    Patrol
  2. 👀2 見つける

    カメラ映像から AI が人・バナナ・ぬいぐるみを探し、見間違いを避けて確定します。

    Reaction
  3. ✋3 止める

    Reaction が Patrol に「止まって」と頼みます。止まったと確認できてから次へ進みます。

    Reaction → Patrol
  4. 🗣4 反応する

    声を出し、腕と腰の動きを再生します。脚は立ったままです。終わると腕を元の姿勢に戻します。

    Reaction → Jetson
  5. 🚶5 歩き出す

    Reaction が「再開して」と頼み、Patrol が残りの距離ぶんを歩きます。

    Reaction → Patrol

5 いつ何が起きるか sequence

「見つけて、止めて、反応して、再開する」1 回分を上から下へ並べました。A の帯の通信（Move・odom・LiDAR）は、B 以降もずっと流れ続けています。

それぞれのプログラムが回すループの周期は、7 の表にまとめました。ここでは、判断の中身が分かりにくい Patrol と Reaction のフローチャートを示します。

Patrol：5 段の巡回

7 誰が何を握っているか responsibility

部品ごとに、動く場所、使う技術、回るループ、読むもの、制御するものを並べました。脚と腕は別の口で動くので、歩きながら腕を振ることはコード上は可能です。それを防いでいるのは、Patrol を止めてから腕を動かす順番の制御（pause → react → resume）です。

部品場所技術回るループ読むもの制御するもの
Reaction操作PCPython・OpenCV・YOLO11n（CUDA）約 10ms ごとに最新の映像と検出結果を確認（YOLO は別スレッド）カメラ映像（JPEG）、Patrol の状態Patrol の pause/resume、音声、腕の依頼（自分では動かさない）

腕と腰は rt/arm_sdk の weight で「内蔵コントローラから借りる量」を決めます。1 で完全に借り、0 で返します。反応が終わったら q0（初期姿勢）に戻してから weight を 0 にします。

8 用語集 glossary

場所・部品

操作PC
運営側の Linux PC（GPU 付き）。映像の認識と、全体の順番決めを担当します。
JetsonPC2・Orin NX
G1 に搭載された小型コンピュータ。操作PC の指示を G1 の SDK に橋渡しします。
Patrolパトロール
決まったコースを歩く係のプログラム。操作PC で動き、歩行命令だけを出します。
Reactionリアクション
映像を見て判断し、止める・声・腕の順番を決めるプログラム。操作PC で動きます。
relay中継
通信を受け取って別の形で渡す小さなプログラム。Jetson 上で動きます。
resident常駐
起動したまま待機するプログラム。毎回の立ち上げ待ちをなくします。
MotionDecode
腕の動き（目標角の時系列）を再生する仕組み。
YOLO11n
画像から物体を見つける軽量な AI モデル。GPU で動かします。

センサー・測定値

LiDARLivox MID360
レーザーで周りの距離を測るセンサー。前方に障害物があるかの判定に使います。
IMU
傾きと回転を測るセンサー。旋回の角度に使います。
odomオドメトリ
どれだけ進んだかの推定値。G1 内蔵の SLAM が出します。
テレメトリ
ロボットから送られてくる測定値（odom・IMU）の総称。
CLEAR / BLOCKED
前方に障害物がない／ある、という LiDAR の判定。

通信

Unitree SDK
G1 を動かす公式ライブラリ（unitree_sdk2py）。歩行は LocoClient、音声は AudioClient、映像は VideoClient。
DDS
G1 の内部で部品同士が使うメッセージ通信。rt/… という名前（トピック）で受け渡します。
UDP
軽い通信。届かなくても再送しないので、周期的に流す指示や測定値に向きます。
SSH
操作PC から Jetson へ安全につなぐ通信。映像・音声・腕の依頼に使います。
Unix socket
同じ PC の中のプログラム同士の通信。Patrol と Reaction の連絡に使います。

命令・制御

Move / StopMove
歩行コントローラへの命令。Move は前進・横・旋回の速さを指定し、StopMove は止めます。
watchdog見張り
一定時間指示が来なければ自動で止める仕組み。relay は 0.40 秒で止めます。
閉ループodom ループ・IMU yaw ループ
測りながら動き、目標に届いたら止める制御。「0.30 m/s で進め」と速さだけ指示しても、床の滑りなどで実際の距離はずれます。そこで Patrol は tick ごとに測定値を読みます。前進は odom（進んだ距離）で「2 m / 4 m 進んだか」、旋回は IMU の yaw（向き）で「180° 回ったか」を判定します。一時停止したときも、残り距離・残り角度を計算し直して再開できます。
tick
ループの 1 回分。
pause / resume
Patrol の一時停止と再開。Reaction が頼みます。
preflight
腕を動かす前の事前確認。腕が静止しているかを見ます。
rt/arm_sdk・weight・q0
腕と腰を内蔵コントローラから借りる口、借りる量（0〜1）、初期姿勢。
cooldown
反応のあとに次の反応を受け付けない待ち時間（2.0 秒）。
found / surprise
反応の種類。人は found、バナナとぬいぐるみは surprise。
