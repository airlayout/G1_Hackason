# Pepper 認識アプリ（Streamlit・CPU）

カメラの映像から **人・物（椅子など）・手の動き** を認識し、画面で割り当てた操作（**その方向を見る・正面を見る・手を振る**）を Pepper に送るアプリ。
認識は CPU だけで動く（GPU・CUDA・ROS は使わない）。Pepper とは **NAOqi API（ポート 9559）** で直接つなぐ。

**回る・進むは無い。** 試運転でも本番でも送らない（規則に書いても読み込みの時点で弾く）。

## 起動（ゲーミング PC＝Ubuntu 24.04）

```bash
cd Entame/real/pepper_app
./setup_ubuntu.sh   # 初回だけ。.venv（約 1.8GB、CPU 版 torch）と YOLO の重みを用意する
./run_app.sh        # http://<この PC の IP>:8501 で開く
```

OMEN（共用のゲーミング PC）なら、同じルータからは `http://192.168.0.167:8501`、Tailscale からは `http://100.99.102.70:8501`。
Mac で開発するときは `uv venv --python 3.12 .venv && uv pip install -r requirements.txt` のあと `python -m pepperapp.weights`。

## 使い方

1. 左の「映像の入口」は最初から「Pepper のカメラ」（192.168.0.85、QVGA）。Pepper が無いときは「動画・画像ファイル」に切り替えると見本画像で試せる。「開始」で映像に枠と棒人間が出る
2. 「割り当て」タブで「きっかけ → 操作」を編集し、「保存して反映」（`rules/rules.yaml` に保存）
3. Pepper で試すとき
   1. 左に Pepper の IP を入れ、「接続確認」タブで NAOqi の版・起きているか・手を振るアニメーションの名前を確かめる
   2. 「映像の入口: Pepper のカメラ」「動かす先: 本番」にし、腕の届く範囲を確かめたチェックを入れて「開始」
   3. 本番は「反応しない」状態で始まる。上の「反応を始める」で割り当てが動き出す

## きっかけ（認識）

| きっかけ | いつ出るか |
|---|---|
| 人が現れた | 誰もいない状態から、人が 0.5 秒続けて見えた |
| 人が見えている間（追従） | 人が見えている間ずっと（待ち時間で間引く。首で追うとき用） |
| 人がいなくなった | 1.5 秒続けて誰も見えない |
| 人が近づいた | いちばん大きい人の枠の高さが画面の 60% 以上になった（50% を下回ると戻る） |
| 手を挙げた | 手首が肩より上で、0.8 秒ほぼ動かない |
| 両手を挙げた | 両手首が鼻より上で 0.8 秒 |
| 手を振った | 手首が肘より上で、1.5 秒以内に左右へ 2 回以上切り返す（振れ幅は肩幅の 0.15 倍以上）。手を下ろすと 0.3 秒で終わる（1 枚だけ手首を見失っても途切れない） |
| 見つけた: 物 | 左で選んだ物（既定は椅子）が 0.5 秒続けて見えた |

- 手の動きは YOLO11n-pose の 17 個の関節点（鼻・肩・肘・手首…）の **時間の動き** から決まりで判定する。距離に左右されないよう、長さは肩幅で割っている
- 「人」は姿勢モデルの結果のうち、物体検出モデルも人と見た所（重なり IoU 0.4 以上）だけを使う。姿勢モデルだけだと、見本画像の犬を人と判定した（縮め方だけで 0.45〜0.73 と揺れ、しきい値では防げなかった）
- きっかけは「始まった瞬間」に 1 回だけ出る。振り続けている間は出ない

## 操作

| 操作 | Pepper で行うこと |
|---|---|
| その方向を見る | 画面の中の位置を首の角度に直し、今の首の角度に足す（上カメラの画角 57.2°×44.3°）。yaw は ±1.0 rad、pitch は −0.4〜+0.3 rad に収め、速さは最大の 15%。首が着くまで待つ（`angleInterpolationWithSpeed`）。0.5 秒より古いきっかけでは見ない（首がもう動いているかもしれないため） |
| 正面を見る | yaw 0、pitch −0.15 rad |
| 手を振る | `ALAnimationPlayer.run("animations/Stand/Gestures/Hey_1")`。左の欄で変えられるが、`animations/Stand/Gestures/Hey_<番号>` 以外は受け付けない（体全体が動くアニメーションもあるため） |

割り当ての決まり: 上の行ほど優先。指令は同時に 1 つだけで、前の指令から 1 秒以上あける。Pepper が動作中に起きたきっかけは 2 秒まで待つ。規則ごとに待ち時間があり、割り当てを保存しても変えていない規則の待ち時間は引き継ぐ。

## 安全の決まり

- 既定は試運転（Pepper に何も送らない）。本番は「腕の届く範囲を確かめた」チェックが要り、反応しない状態で始まる
- 首の角度は 2 重に確かめる（`LookConfig` の範囲と、送る直前の関節の可動域）
- 接続中は `ALBasicAwareness` を止める（Pepper が自分で首を振って「見る」と喧嘩するため）。停止・アプリの終了で戻す
- 起きていない Pepper の首と腕は動かない（「接続確認」で分かる）。このアプリは起こさない
- 制御役はサーバに 1 つだけ。どのタブから開始・停止しても同じ 1 つを操作し、同時に押しても 2 つ目のループは残らない
- ⚠️ **画面に認証は無い。** `0.0.0.0:8501` で待ち受けるので、同じ LAN か Tailscale にいる人は誰でも本番に切り替えられる。
  信頼できるネットワークだけで使う。自分の PC からだけ開くなら `./run_app.sh --server.address 127.0.0.1`

## Pepper との接続

**アプリの既定は Wi-Fi の 192.168.0.85・QVGA。** Pepper 本体（NAOqi 2.5.10.907）は、有線なら 192.168.123.99（OMEN の有線ポート G1-ethernet、192.168.123.200 と頭の後ろの LAN 端子を直結）。
192.168.0.85 はルータの DHCP が配ったアドレスなので、変わることがある。固定したいときはルータ（WR1502X）で予約する。
Wi-Fi に見える 192.168.0.211 は胸のタブレット（Android）で、9559 番は無いので繋がらない。

2026-10-09 に、本体を 2.4GHz の `Physical_AI` にもつないだ（**192.168.0.85**、DHCP。Pepper がパスワードを覚え、次からは自動でつながる）。
ただし Wi-Fi 越しはカメラが遅い（QVGA 4.2fps、VGA 1.1fps。有線は VGA 29.7fps）。**映像を使う認識は有線、首と手振りだけなら Wi-Fi でも可。**
5GHz の `Physical_AI_5G` は「つなぎに行ってすぐ中断（OperationAborted）」で失敗した。本体の Wi-Fi の国の設定が未設定なのが疑わしい。

本体を Wi-Fi につなぎ直すときは、有線でつないだ状態で次を実行する（パスワードはその場で入力し、保存しない）。

```bash
.venv/bin/python tools/connect_pepper_wifi.py --list                 # 見える Wi-Fi の一覧（何も変えない）
.venv/bin/python tools/connect_pepper_wifi.py --ssid Physical_AI_5G  # パスワードを聞かれる
```

`qi` 3.1.5（PyPI、Python 3.12 の Linux 版あり）で `tcp://<IP>:9559` に繋ぐ。使うサービスは次のとおり。

| サービス | 用途 |
|---|---|
| ALVideoDevice | 頭の上カメラ（VGA/QVGA、RGB）を `getImageRemote` で取る |
| ALMotion | `getAngles` / `setAngles`（HeadYaw・HeadPitch だけ）、`robotIsWakeUp` |
| ALAnimationPlayer | 手を振るアニメーション |
| ALBasicAwareness | `pauseAwareness` / `resumeAwareness` |
| ALSystem・ALBehaviorManager | 接続確認（読み取りだけ） |

NAOqi 2.9（Android の QiSDK の Pepper）は外から 9503 番と認証が要るので、この方式では繋がらない。

## 確かめたこと・まだのこと（2026-10-09）

確かめたこと
- テスト 90 件が Mac と OMEN の両方で通る。Pepper の部分は、本物の `qi` の通信を手元の qi サービス相手に通して試している（画像のバイト列が NAOqi と同じ Raw 型で届くことも含む）
- OMEN の CPU（Core Ultra 7 265F、4 スレッド、DoorMan の学習中）で、姿勢と物体検出の 2 つを合わせて 1 枚 35 ms。見本画像（10 fps で流す）で 10 fps
- 画面を Mac のヘッドレス Chrome から Tailscale 越しに開き、開始・割り当て・ログ・停止とスマホ幅の表示を確かめた
- コードレビュー（別エージェント）の指摘のうち、開始・停止の競合、アニメーション名の制限、停止直後の指令、終了時の後片付けなどを直した

まだのこと
- 本物の Pepper（有線）で、接続確認（NAOqi 2.5.10.907、`Hey_1`〜`Hey_10`）とカメラ（VGA 29.7fps）、試運転での認識（椅子）までは確かめた。**首と腕を実際に動かすのはまだ**
- Pepper のカメラだと推論が 134ms・3.4fps と、見本画像（35ms）より遅かった。原因は未確定
- 手の動きのしきい値は合成した関節点で試しただけ。Pepper のカメラ（約 1.2m の高さ）で 1・2・3m の録画を撮って調整する
- 遠くの人（3m 以上）は関節点がぶれやすい

## ファイル

```
app.py                  Streamlit の入口
pepperapp/
  observations.py       検出結果の型（人・物・注視点）
  detector.py           YOLO11n の姿勢（ByteTrack の ID 付き）と物体検出
  gestures.py           手を挙げる・両手・手を振るの判定
  events.py             きっかけ（保持時間つきの立ち上がり）
  rules.py              割り当て（YAML、優先順、待ち時間）
  robot.py              首の角度の計算、試運転、1 つずつ実行する仕組み
  naoqi_robot.py        Pepper（NAOqi API）
  sources.py            映像の入口（ファイル・USB カメラ・Pepper）
  pipeline.py           裏で回すループと画面用の状態
  controller.py         設定から組み立てる（サーバに 1 つ）
  ui_settings.py, ui_tabs.py, labels.py
  weights.py            YOLO の重み（版と SHA256 を固定）
rules/default.yaml      既定の割り当て
tests/                  pytest（.venv/bin/python -m pytest -q）
```
