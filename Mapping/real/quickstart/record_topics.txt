# 記録するトピックの定義。**ここ以外に直書きしない**（check_link.sh 手順 8 が検査する）
#
# ## なぜ要るのか
#
# 2026-09-10 の実機 3 本（runs/stage_20260910T182639_r{1,2,3}）は run_stage.sh の
# 直書きで録った。そこに **IMU が入っていなかった**。翌 09-11 に「歩行中のすべりの
# 原因は IMU か」を確かめようとしたとき、**記録からは確かめられず**、稼働中の DDS を
# 別に測り直す羽目になった。記録しなかったデータは取り返せない。
#
# 直書きが 5 箇所に散っていたのが原因なので、定義をここ 1 箇所に集める。
# （`docker/record-topics.sh` は別系統の古い実装。参照も流用もしない）
#
# ## 書き方
#
#   <トピック名>   <範囲>   # 説明
#
# 範囲:
#   sensor   生センサ。live の `ros2 bag record` と PC2 の DDS 直記録の**両方**で必ず録る
#   ros      ROS 側にしか無い。**PC2 の DDS 直記録には存在しない**（DDS に流れていない）
#   mapping  内蔵 SLAM の出力。`record_dds_to_bag.py --with-mapping` のときだけ足す
#
# ## 読み方（bash 3.2。配列を使わない）
#
#   awk '/^[[:space:]]*#/{next} $2=="sensor"||$2=="ros"{print $1}' record_topics.txt
#
# 追加するときは `record_dds_to_bag.py` の KNOWN_TOPICS にも型を足すこと
# （足し忘れは check_link.sh 手順 8 が NG にする）。

/utlidar/cloud_livox_mid360    sensor    # 生 LiDAR。9.95 Hz / 約 4.4 MB/s
/utlidar/imu_livox_mid360      sensor    # 199.6 Hz。⚠️ 無いと後から掛け直せない（上の経緯）
/dog_odom                      sensor    # 純正の脚 odometry（nav_msgs/Odometry、1008 Hz、odom->robot_center）。
                                         # 2026-09-12 に存在を確認。旋回中の「並進していない」を知る唯一の独立な情報源。
                                         # ⚠️ 09-12 の旋回ベンチ 2 本はこれを録っておらず、脚 odom が旋回で滑らないかを
                                         # 後から確かめられなかった。IMU と同じ轍。約 0.75 MB/s
/tf                            ros       # MOLA の map->base_link。測位を後から検算する唯一の手
/tf_static                     ros       # base_link->livox_frame の取付
/unitree/slam_mapping/points   mapping   # 内蔵 SLAM の地図座標系の点群
/unitree/slam_mapping/odom     mapping   # 内蔵 SLAM の自己位置

# ## なぜ増やすのか（3 度目の「録っておけばよかった」）
#
# 09-10 は IMU が無くて原因を追えず、09-12 は脚 odom が無くて追えなかった。
# **09-13 に 3 度目をやった** —— クリック走行 4 本目で「経路は毎秒引けているのに
# 機体が 80 秒まったく動かない」という状態になり、`Failed to make progress` →
# `Spin` → 見張りが 120 秒でキャンセル、で終わった。
# **何が指令されていたのかを後から確かめられなかった。`/cmd_vel` を録っていなかったから。**
#
# ## 方針: 探索段階では「安い物は全部録る」
#
# 実測した追加ぶんは **約 +0.37 MB/s（+7%）**。そのほとんどは
# `/global_costmap/costmap`（780x431 セル・always_send_full_costmap・約 1 Hz で 0.34 MB/s）で、
# 残りは合計しても 0.03 MB/s に満たない。**LiDAR の 4.4 MB/s に比べれば誤差**である。
#
# ⚠️ **存在しないトピックを並べても記録は壊れない**（2026-09-14 に実測）。
# rosbag2 は在るものだけ購読して録り続ける（`Listening for topics...` のまま待つ）。
# **だから「まだ使うか分からない物」も書いておいてよい。**

# ⚠️ **効くのはディスクの方**。1 本 5 分で約 1.6 GB になる。置き場を先に決めること
