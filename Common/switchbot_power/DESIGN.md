# SwitchBot Bot による G1 電源 ON/OFF — 設計書

Hub なし・Linux（Ubuntu）から BLE で直接 SwitchBot Bot を操作し、G1 バッテリーの電源ボタンを押す。
実装は `core.py`（本体）、`ble.py`（BLE 実体）、`cli.py`（CLI。`Common/` で `python3 -m switchbot_power ...`）。テストは `Common/tests/test_switchbot_power.py`。

> **実機（Bot 本体）での動作は未確認。** 下の「調べた仕様」は PySwitchbot 2.10.0 のソースを読んだ結果で、
> 「実機未確認」と書いた項目は Bot を手元に置いて確かめるまで断定しない。

## 1. 調べた仕様（PySwitchbot 2.10.0 のソースより）

BLE GATT でコマンドを書き込む。Hub もクラウドも不要。

| 操作 | コマンド | PySwitchbot | 備考 |
|---|---|---|---|
| 押す→戻る | `57 01 00` | `press()` | **Press モード**ではアームが降りて戻る。**Switch モードではトグル**になる |
| ON / OFF | `57 01 01` / `57 01 02` | `turn_on()` / `turn_off()` | Switch モード用 |
| アームを下げる | `57 01 03` | `hand_down()` | 押しっぱなしにできる。Press モードでも**受理され、指定秒数だけ保持される**（実機確認済み §8） |
| アームを上げる | `57 01 04` | `hand_up()` | 同上 |
| 長押し秒数の設定 | `57 0f 08 <秒>` | `set_long_press(秒)` | Bot 本体に保存される設定。この秒数ぶん `press` が押し続ける |
| 基本情報の取得 | `57 02` | `get_basic_info()` | 下表 |

パスワード設定時は、コマンドの先頭に CRC32 を付けて送る（PySwitchbot が処理する）。

### 取得できる状態（自動テストの根拠）

| 状態 | 取得元 | 取れる値 |
|---|---|---|
| 広告（スキャンだけ・接続不要） | `GetSwitchbotDevices` | `switchMode`、`isOn`（Switch モード時のみ。Press モードは常に False）、`battery`、RSSI |
| 基本情報（GATT 接続が必要） | `get_basic_info()` | `battery`、`firmware`、`strength`、`switchMode`、`inverseDirection`、`holdSeconds`、`timers` |
| コマンド応答 | 各コマンドの戻り値 | 先頭バイトが 1 か 5 なら受理。それ以外は `SwitchbotOperationError` |

**取得できないもの**: アームの現在位置、ボタンが物理的に押せたか。
→ 目視に頼らないため、次の 2 段で自動検証する。

1. **Bot 側**: 実行前に基本情報を読み、`switchMode == False`（Press モード）と、タップ用途なら `holdSeconds == 0` を確認する。違えば実行を拒否する。コマンドの応答コードが失敗なら例外にする。
2. **G1 側（本当の成否）**: `--verify-ip` で G1 の IP に ping を打ち、ON なら「到達するまで」、OFF なら「到達しなくなるまで」を待つ。タイムアウトなら失敗として終了コード 1 を返す。

## 2. G1 の電源ボタンの手順

`Common/g1-safety/02-start-stop.md` より。

- **起動**: 短く 1 回押す → 離す → 続けて 2 秒以上長押し。約 1 分待つ。
- **停止**: 2 秒以上長押し。**立位のまま切らない**（ダンピングへ移し、座位か吊り下げで支えてから）。

## 3. 提供する操作

| CLI | 動作 |
|---|---|
| `scan` | 近くの Bot を一覧（アドレス・モード・電池・RSSI） |
| `set-hold --seconds N` | Bot の長押し設定（本体に保存）を変更。短押しは 0 |
| `info` | 基本情報を表示（モード・長押し秒数・電池） |
| `push-once` | 押して**すぐ離す**（`press`） |
| `push-hold --seconds N` | N 秒**押し続けて**離す |
| `g1-on` | `push-once` → 間隔 → `push-hold`（起動手順） |
| `g1-off --confirm-damped` | `push-hold`（停止手順）。**ダンピング済みの確認フラグが必須** |

共通: `--address`（または環境変数 `SWITCHBOT_ADDRESS`）、パスワードは環境変数 `SWITCHBOT_PASSWORD` のみ
（コマンドラインに残さない）。`--fake` は BLE を使わず、押下・解放のタイムラインを表示する（Bot なしの動作確認用）。

### 押しっぱなしの 2 方式（`--hold-mode`）

| 方式 | 仕組み | 長所 | 短所 |
|---|---|---|---|
| `host`（既定） | `hand_down` → 待つ → `hand_up` | 秒数を小数で指定できる。Bot の設定を変えない | PC が途中で落ちるとアームが降りたまま。**実機未確認**（Press モードで `hand_down` が効くか） |
| `device` | `set_long_press(N)` → `press` → 待つ → `set_long_press(0)` | 解放は Bot 自身が行うので PC が落ちても戻る | 秒数は整数。Bot の設定を書き換える |

`host` が実機で効かなければ `device` を使う。どちらが効くかは Bench で決める。

## 4. 安全設計

- **解放を必ず試みる**: `push-hold` は `try/finally` で `hand_up` を最大 3 回送る。待機中の Ctrl+C（キャンセル）でも解放してから終了する。3 回失敗したら「アームが降りたままの可能性」を明示して失敗にする。
- **押下時間に上限**: `0.1 ≤ 秒 ≤ 10`。長すぎる指定は拒否。
- **電源 OFF は確認フラグ必須**: `--confirm-damped` が無ければ実行しない。
- **自動リトライしない**: `g1-on` が失敗しても再実行しない（トグル動作の誤作動を避ける）。失敗は終了コードで返し、再実行は人が判断する。
- **Press モード以外は実行を拒否**: Switch モードの `press` はトグルになり、状態が分からなくなる。

## 5. 時間パラメータ（既定値。実機で調整する）

| 名前 | 既定 | 根拠 |
|---|---|---|
| `G1_ON_GAP_S`（短押しの後の間隔） | 0.5 秒 | 手順書は「続けて」としか書かない。**実機で調整** |
| `G1_HOLD_S`（長押し） | 3.0 秒 | 手順は 2 秒以上。余裕を 1 秒 |
| `VERIFY_TIMEOUT_S`（G1 到達確認） | 120 秒 | 起動は約 1 分 |

間隔は `press` コマンドの応答が返った時点から数える。`press` 自体の押下・復帰に要する時間は Bot の機械的な速さで決まる。

## 6. テスト計画

**自動（Bot も G1 も不要。`Common/tests/run_tests.sh` に含み、CI でも実行される）**

- 仮想時計つきの偽 Bot で、押下→解放の順序・保持時間・間隔が正確か。
- 待機中のキャンセル、`hand_up` の失敗リトライで、解放が必ず試みられるか。
- Switch モード、`holdSeconds != 0` で拒否されるか。上限・下限・確認フラグの検証。
- G1 到達確認の合否判定（偽の ping）。
- `hold-mode device` の設定と復元（例外時も復元）。

**実機（Bot を用意したとき。自動化できる範囲は自動）**

1. `scan` で Bot が見え、`info` が Press モード・`holdSeconds=0` を返す。
2. `push-once`・`push-hold` の応答コードが成功。アームの動きだけは目視（取得不能）。
3. G1 電源ボタンに取り付け、`g1-on --verify-ip <G1>` が自動で成功判定を出す。
4. `host` の `hand_down` が Press モードで効くか。効かなければ `device` 方式。

## 7. 依存関係

`pip install pyswitchbot==2.10.0`（Python 3.11 以上、`bleak` を含む）。Linux は BlueZ が必要。
`core.py` は標準ライブラリのみなので、PySwitchbot は `ble.py` の中で**遅延 import** する（未インストールでもテストと `--fake` は動く）。

## 8. 実機での測定結果（2026-10-01、Bot 1 台、ファームウェア 6.6、Mac から BLE）

| 項目 | 結果 |
|---|---|
| `scan`（広告のみ） | 検出できた。Press モード、電池を取得できた |
| `info`（GATT） | 取得できた。`holdSeconds` は **1**（初期値ではなく、この個体の設定） |
| `push-once`（`holdSeconds=1` のとき） | 安全チェックで**拒否**（設計どおり） |
| `set-hold --seconds 0` | 設定を変更し、読み戻しで 0 を確認（許可を得て実施。**この Bot の保存設定は 1 → 0 に変わった**） |
| `push-once`（`holdSeconds=0`） | 成功（終了コード 0）。Bot が動いた |
| `hand_down` | Press モードで**受理された**（応答 `01ff00`）。Bot が物理的に動いたことを目視で確認 |
| `hand_up` の応答 | `hand_down` の直後は **`03ff00`（動作中）で拒否**され、約 2〜3 秒後に `01ff00`（成功）へ変わる |
| `push-hold`（host）3 秒 | 成功（終了コード 0） |
| `push-hold`（host）5 秒 | 成功。**アームは 5 秒間下がったままだった**（目視。`holdSeconds=1` でも影響しない） |

- 拒否コード `03` の間にリトライを数ミリ秒間隔で打つと全部失敗し、「解放失敗」と誤判定した。**0.4 秒間隔で最大 12 回（約 5 秒）待つ**ように直した（`RELEASE_RETRIES` / `RELEASE_RETRY_INTERVAL_S`）。
- 確認済み: `host` 方式はこの Bot で指定秒数ぶん保持される。`device` 方式は未試験（`host` が効くので必須ではない）。
- `device` 方式は、実行前の `holdSeconds` を読んで**元の値に戻す**（以前は 0 に戻していた）。

### 8.1 Bot の動作時間（実測。G1 の「短押し → 長押し」の間隔を決める）

| 測定 | 結果 |
|---|---|
| `press` の後、`hand_down` が受理されるまで | 約 **2.9 秒**（それまで `03` 動作中） |
| `hand_down` の後、`hand_up` が受理されるまで | 約 **1.8〜2.9 秒**（それまで `03`） |
| 動作直後 0.1 秒以内の命令 | 受理される（動作の始まる前に通る） |
| `hand_down` → 0.3 秒 → `hand_up` | `hand_up` は約 1.8 秒まで通らない。**ソフトだけでは短い接触時間は作れない** |

- 「短押し → すぐ離す → 長押し」の間隔は、**Bot の機械速度で最短約 3 秒**になる。`G1_ON_GAP_S`（0.5 秒）は下限にすぎず、実際は `hand_down` が受理された時点で長押しが始まる。
- そのため `hand_down` も、受理されるまで動作中の間は 0.2 秒間隔で最大 30 回（約 6 秒）再送する（`ACQUIRE_RETRIES`）。長押しの時間は**受理された時点から**数える。
- **G1 が「短押しから約 3 秒後の長押し」で起動するかは未確認**。G1 に取り付けて確かめる。起動しなければ、Bot の動きを速くする（`strength`、Bot の取り付け位置・押し込み量）か、別の手段を検討する。

`g1-on` 通し（机上、G1 なし）: 短押し → 長押し 3 秒を、終了コード 0 で完走（約 18 秒。うち大半は BLE 探索・接続）。
