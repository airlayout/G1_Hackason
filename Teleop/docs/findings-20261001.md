# 実機で判明した事実（2026-10-01）

**すべて実測。推測は「推測」と明記する。**
次に実機を触る人が同じ切り分けを繰り返さずに済むように残す。

機体: G1 29自由度 / `mode_machine=5` / 設置: 吊り下げ（足は接地）

---

## 1. この機体は `rt/arm_sdk`（制御権の委譲）に応じない

**実測。** `tools/armsdk_probe.py` で左肩ピッチを 0.05 rad 動かす指令を出した結果:

```
対象: L_ShoulderPitch (motor 15)  現在 -0.1090 rad → 目標 -0.0590 rad
  ① 制御権 0→1 (2秒)   weight=1.00  指令=-0.1090  実測=-0.1090  偏差=+0.0000
  ② 目標へ   (2秒)     weight=1.00  指令=-0.0590  実測=-0.1090  偏差=+0.0000

指令した変位 : +0.0500 rad  /  実測の最大変位: +0.0000 rad
```

制御権 `weight=1.00` を送り、指令値も正しく出ているのに**実測変位はゼロ**。
エラーは出ない。

**帰結:** `ai` を稼働させたまま腕だけ操作する経路は使えない。
**「`ai` を解除 → デバッグ状態 + `rt/lowcmd`」が唯一の経路になる。**

この挙動は `g1-starter-kit` の作者が検証した機体でも同じだった、とドキュメントに
記載がある。機体個体の問題ではなく、この世代に共通する可能性がある（推測）。

---

## 2. `ai` を解除すると全モータがゼロトルクに落ちる

**実測。** `mode_check.py --release` の前後:

| | `rt/lowcmd` | 腕 mode | 脚 mode |
|---|---|---|---|
| 解除前 | 1000.7 Hz（`ai` が占有） | 1 | 1 |
| 解除後 | **0.0 Hz**（空いた） | **0** | **0** |

道は狙いどおり空くが、同時にモータの電気が切れる。

**復帰はリモコンのダンピング（FSM 1）のみ。** 次の2つは効かない。

- 指令メッセージの `motor_cmd[].mode = 1` → 無視される
- `LocoClient.Damp()` → `ai` 解除中は loco サービスが応答しない（`code=3102`）

### 検証した仮説と結果

「`ai` 稼働中にダンピングへ入れてから解除すれば、モータが有効のまま残るのではないか」
という仮説を実機で試した。`g1-starter-kit` のドキュメントでは未検証とされていた点。

**結果: 残らなかった。** ダンピング済み（腕 mode=1）かつ `ai` 稼働中の状態から
解除しても、やはり全モータが mode=0 に落ちた。**この回避策は使えない。**

## 3. ダンピングは指令が届かないと数十秒で切れる

**実測。** デバッグ状態でダンピングに入れて `mode=1` を確認した約30秒後、
テレオペを起動しようとすると起動前チェックで中断された。再確認すると `mode=0`。

```
[中断] 腕のモータが無効です（rt/lowstate の motor_state[].mode = 0 = ゼロトルク）
```

**帰結:** ダンピングは「状態」ではなく「指令を送り続けて維持するもの」。
人間が確認してから手で起動するまでの往復が、そのままデッドタイムになる。

**対策:** `rt/lowstate` を監視し、`mode=1` を検出した瞬間（0.05秒以内）に
テレオペを自動起動する（`tools/watch_and_launch.py`）。

この方式に変えてから3回とも成功した（検出 71.7秒 / 232.9秒 / 259.0秒 → いずれも即起動）。
**手作業で起動した回は失敗した**（検出から約30秒後に `mode=0` へ戻り、起動前チェックで中断）。

**ただし、起動できても通電が維持されるわけではない。** 次項を参照。

## 3b. teleop が `mode=1` を送り続けても通電は維持されない

**実測。** teleop 稼働中に、送信内容と実測モードを12秒間観測した。

```
  [ 2s] lowcmd=  246Hz  送信mode=[1] kp=80  →  実測mode=[0]
  [ 4s] lowcmd=  247Hz  送信mode=[1] kp=80  →  実測mode=[0]
  [ 6s] lowcmd=  246Hz  送信mode=[1] kp=80  →  実測mode=[0]
  （6回連続、すべて同じ）
```

**teleop は `motor_cmd[].mode=1` を正しく送っているのに、モータは `mode=0` のまま。**

当初は「teleop が 250Hz で送り続けるのでダンピングが維持される」と考えていたが、
**誤りだった。** 追従が成功した回は、単にその時点でまだダンピングが切れていなかっただけ。

**帰結:**

- 通電はリモコンのFSM（ダンピング）でしか維持できず、**時間とともに切れる**
- この状態で `CMD_START` を送っても**腕は 1mm も動かない**（送信は成功と表示される）
- **作業のたびにダンピングを入れ直す必要がある。** 追従を始める直前に入れるのが確実

キットのドキュメントが書いていた「指令側の `motor_cmd[].mode=1` では有効にならない」が
そのとおりだった、という確認でもある。

## 4. `ai` 解除のRPCは散発的に失敗する

**実測。** 1回目は6回連続で `status=3104`（送信成功・返事なし）。
「リモコン側で操作してください」と表示された。

**同じコマンドをもう一度実行したら成功した。** 恒久的な障害ではない。

キットには既にリトライのパッチ（タイムアウト 1.0 → 5.0 秒、6回試行）が
当たっている。**それでも失敗することがある。**

## 5. 腕の目標は「頭から見たコントローラの相対位置」で決まる

公式リリースノート（v1.6）に `use head-yaw-relative arm reference by default` とある。
使用しているキットでは、向き基準だと操作中によそを向いたときに左右がズレるため、
**位置基準**（`arm_reference_mode="head_position"`）に変更されている。

**帰結（操作上の注意）:**

- 手を動かさなくても、**頭が動けば腕の目標が変わる**。振り向く・しゃがむ・歩く、すべて腕の動きになる
- 操作中は立ち位置と頭の高さを保つ
- コントローラはヘッドセットのカメラ視界内（顔の前〜やや横）に保つ。視界外に入ると追従が止まる

## 6. ヘッドセットにロボット視点の映像は出ない（この構成では）

**実測。** テレオペ起動ログ:

```
WARNING  Request to 192.168.123.164:60000 timed out or no response, using local config.
```

`192.168.123.164` は G1 内蔵の PC2。**映像にはPC2側の画像サービスを別途起動する必要がある**が、
今回は起動していない。公式READMEも実機では手動起動が必要としている。

**帰結:** 没入ビューに入ってもパススルー（周囲の現実）しか見えない。
**異常ではない。** G1 を直接目で見ながら操作する前提になる。

## 7. `--motion` 無しの構成では VR 内の緊急停止が使えない

コード上、次は `--motion` 指定時のみ有効:

```python
if args.input_mode == "controller" and args.motion:
    if tele_data.right_ctrl_aButton:      START=False; STOP=True   # 右Aボタンで終了
    if 両スティック押し込み:               loco_wrapper.Damp()      # 緊急ダンピング
```

この機体は `arm_sdk` が効かないため `--motion` を使えない。**帰結:**

- 右Aボタンでの終了、両スティック押し込みの緊急ダンピングは**無効**
- 止める手段は**操作PC側からの終了操作のみ**。最終手段は電源
- 反面、**サムスティックが歩行指令になることもない**（脚が勝手に踏み出す心配はない）

## 8. 追従開始の瞬間に腕の速度上限が 2 → 30 rad/s へ上がる

`speed-restore` パッチの仕様で、上流の既定値に戻す動作。追従の応答性に必要。

**帰結:** コントローラがロボットの手の位置から離れていると、
**その差を埋めるために腕が高速で動く。** 開始前の姿勢合わせは省略できない。

公式READMEも `Align your arm to the robot's initial pose to avoid sudden movements at start.`
と記載している。

## 9. 全29関節が固定されるため、腕を動かすと脚にもトルクが出る

**実測。** 追従中:

| | 開始前 | 追従中 |
|---|---|---|
| 腕トルク最大 | 0.06 Nm | 8.44 Nm |
| 脚トルク最大 | 0.26 Nm | **9.93 Nm** |

テレオペは腕だけでなく**全29関節を固定している**（脚 kp=300）。
腕を動かすと吊り下げの機体が揺れ、脚がそれに抵抗する。

**異常ではない。** 脚関節の能力に対して十分小さい。
