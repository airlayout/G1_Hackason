# 03. 高レベル制御と低レベル制御 — 絶対に知っておくこと

出典: 公式（`MotionSwitcherClient`、デバッグモード、`rt/lowcmd`）と、技術ブログ「Unitree G1 に 3 つめの動作モードがあるって知ってた？」（2026.07）。
**ブログのみ（公式で未検証）**: ユーザ制御（`SwitchToUserCtrl`、`rt/user_lowcmd`）、`InternalFsmMode`。SDK は 2026/7 時点。
**実機で動かす前に、公式ドキュメント・ファームウェア・周囲の安全を確認する。**

## 1. 3 つの制御

| | 高レベル | 低レベル | ユーザ制御 |
|---|---|---|---|
| 指令 | 速度・立つ・止まる | 各関節の角度・ゲイン・トルク | 低レベルと同じ |
| 送り先 | `LocoClient` | `rt/lowcmd` | `rt/user_lowcmd` |
| バランス | **公式が担当** | **自前** | 自前（区間限定） |
| 公式制御と共存 | — | **競合する** | 切り替えで共存 |

- **高レベル**: 「この速度で歩け」。歩行の安定は公式が担保。**本プロジェクトの基本**（`vx` / `vy` / `yaw_rate`）。
- **低レベル**: 関節を直接指令。姿勢・ゲイン・周期・安全停止・復帰を**すべて自前**で作る。
- **ユーザ制御**: `SwitchToUserCtrl()` で入り、`SwitchToInternalCtrl()` で公式に戻る。
  「普段は公式で歩き、必要な区間だけ関節を直接動かす」用。

> 公式: 起動するとモーション制御が自動で動き、速度 0 の指令を送り続ける。
> SDK を使うなら、先に**デバッグモード**（`L2 + R2`）で止める。さもないと指令が競合して G1 がジッターする。
> モード切替は `MotionSwitcherClient`（`CheckMode` / `SelectMode` / `ReleaseMode`）でもできる。

## 2. 絶対に守ること

1. **開始前に状態を確認する。** `GetFsmId()` が想定と違えば**中止**。想定外の状態から関節指令を送らない。
2. **指令は補間して入る。** 現在角から初期姿勢へ数秒かけて近づける。ステップ状の指令を出さない。
   公式の足首サンプルは、最初の 3 秒でゼロ位置へ戻す。座ったまま実行すると脚が動く恐れ（要ソース確認）。
3. **競合させない。** 公式のモーション制御が動いたまま `rt/lowcmd` を送らない。
   デバッグモード（`L2 + R2`）はこの競合を防ぐために歩行制御を止める。
4. **保護は自前で入れる。** 角度範囲・速度の制限、姿勢異常時の停止。
   ユーザ制御を使っても**安全が保証されるわけではない**。
5. **戻り方を決めておく。** 終了時は公式制御へ戻す（`LAST` など）か、ダンピングへ倒す。
   異常終了でも安全側へ倒す。
6. **制御は有線で行う。** 無線は遅延・パケットロスで、止める指令が届かない恐れがある。

## 3. テレオペ（`xr_teleoperate`）との関係

| 起動 | 動作 |
|---|---|
| `--motion` なし | デバッグモード。**腕のみ**制御、他の関節は固定。脚は支えられない |
| `--motion` あり | 公式モーション制御と並行。`R1 + X` が前提（ラン制御は非対応） |
| `--sim` | シミュレーション。**実機には指令が届かない** |

## 4. 戻り先（`InternalFsmMode`）

`LAST`（直前の公式状態）／`PASSIVE`（脱力）／`WALKRUN`（歩行・走行）。
