# Console 要件書（Jetson 常駐版）

最終更新: 2026-10-18 / 対象ブランチ: `feat/console-on-jetson`（`Dev/UI` 宛て）

段階が進むたびに、この文書の「状態」列と「決定の記録」を更新する。設計は [DESIGN.md](DESIGN.md)、検証は [TEST_SPEC.md](TEST_SPEC.md)。

## 1. 目的
- スマホ・外部 PC はブラウザだけで使う。Jetson（PC2、`192.168.123.164`）がコンソール（ハブ）を動かし、G1 だけで完結させる。
- ROS への移行は目的ではない。**外部 PC への依存を減らす**ことが目的。
- 物理リモコンの機能を段階的に置き換える。ただし物理リモコンは最後の砦であり続ける（NF-04）。

## 2. 対象外
- 警備 UI（`G1_HuggingFace/UI`）。
- ロボット内部 LAN（eth0, 192.168.123.x）への公開。
- 低レベル制御（`rt/lowcmd`）、歩行ポリシーの学習・実行。

## 4. 非機能要件・制約
| ID | 内容 |
|---|---|
| NF-01 | ハブは ROS を持たない。Nav2 とのやり取りは localhost の HTTP |
| NF-02 | ハブは標準ライブラリのみ（追加依存なし）。Jetson の Python 3.8 で動く |
| NF-03 | 起動した直後は運動指令を一切出さない（`disarmed`） |
| NF-04 | ソフトの停止は安全規格を満たさない。物理リモコンが最後の砦であることを画面と文書に書く |
| NF-05 | 通信断の検知は「最後に受信してからの経過時間」で行う（TCP の切断検知に頼らない。2026-09-09 の実測で、リンクを切った後ロボットが約 4 秒・約 0.85 m 歩き続けた） |
| NF-06 | ハブが落ちても、指令の `duration` が切れればロボットが自分で止まる（送信周期 < `duration`） |
| NF-07 | 任意コマンド・シェル文字列を受け付けない。実行できるのは `tasks/*.json` に載ったものだけ |
| NF-08 | 通信は平文 HTTP（wlan0）。トークンは LAN 上で盗聴されうるので、運動の安全をトークンだけに頼らない |
| NF-09 | `G1_ARM`（sudo で手動で開けるゲート）と `enable_navigation` を自動化しない |
| NF-10 | `rt/lowcmd`・`rt/api/sport/*`・`rt/api/loco/*`・`rt/arm_sdk` へのトピック送信は常に拒否 |
| NF-11 | 実測と推測を分ける。測っていない値は「未確認」と書き、推測で埋めない |
